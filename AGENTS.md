# Exhaust: instructions for agents

Exhaust is a note-taking and knowledge-base app written in **C** (C11). **Stay in C.** `README.md` is the spec; the current release's build spec is `docs/0.1.0.md`.

## Goal
Release 0.1.0 fits **every specification in the README**. Items marked *(later)* or *(optional)* may be stubs in the first demo, but must exist as disabled, clearly labeled entries where the README places them. Things listed under the README's **Non-goals** are not built. `*(optional)*` means the feature uses the network and is off by default. Other features that are off by default, such as Vim mode, are not marked `*(optional)*`. If you deviate from the README, update the README in the same change.

## Other languages
C for all of Exhaust's own code, with these exceptions only:
- **Lua** for plugins.
- **Rust** only for the AccessKit screen reader bridge (`src/a11y/`), behind a small C wrapper.
- **Objective-C**, at most 150 lines, only in `src/platform/` for macOS (trash and similar).
- **Assembly**, only the vendored lib-Peep (NASM for x86-64, the GNU assembler for ARM64). No assembly in Exhaust's own sources.
- **JavaScript** only for the web clipper browser extension in `extras/clipper/`. It runs in the user's own browser, not in Exhaust.

Never add a web browser, web view or JavaScript engine to Exhaust itself.

## Hard rules
- **Never write to, move, rename or reorganize users' notes** except through an action the user takes (typing in a note, which Exhaust saves continuously; a link-safe rename after confirmation; importing). Sorting and grouping change presentation only. Never reformat YAML properties or Markdown the user did not edit. `.base` files belong to Exhaust and may be rewritten, but unknown keys must be kept.
- **Privacy:** no network requests, telemetry or accounts by default. Items marked *(optional)* are off until the user turns them on.
- **Where data lives:** settings, themes, snippets, hotkeys and workspaces are plain text in a `.exhaust` folder inside the vault. The search index and other caches live in the **OS cache folder, keyed by vault id, never inside the vault** (a SQLite file in a synced folder corrupts). The index is a cache and must always be rebuildable from the notes.
- **Recovery journal and session state are user data.** They live in the OS local-data folder, keyed by vault, **not** the OS cache folder (the OS may clear a cache) and **not** inside the vault (sync tools would copy them between devices); the exact folders are in `docs/formats.md`. Never delete them except after the text is safely in the note file, and never rebuild them from scratch. Exhaust saves continuously (see the README's Saving): never add a code path that can lose typed text.
- Must run on Windows, Linux (Wayland and X11) and macOS. No display-server-specific code. Platform code lives in `src/platform/`.
- Dependencies must be compatible with the Unlicense. Prefer public domain or permissive libraries. Never add GPL or AGPL code. LGPL libraries (libmpv) are loaded at run time, never linked. Record each dependency and its license in the README's table when you add it, after confirming the license yourself.
- Accessibility is designed in from the first slice: keyboard navigation, scalable text, high contrast, and an accessibility tree for every widget. No hard-coded colors, sizes or fonts: use theme tokens from slice 1a-iv.
- Every feature registers its commands in the command registry and its switch in the feature-toggle registry from sub-slice 2d onward.

## Efficiency and input latency (read this before you write UI or index code)
Exhaust's first promise is that it is fast and never in the way. The user hand-tests every build with a real mouse and keyboard, and **felt lag is the bug they notice first** (a window that fell seconds behind while resizing; an Enter that waited for a re-tokenize). Green CI is not proof: unit tests passed while the real loop lagged.
- **Budgets.** Handling an input event: under 16 ms. A frame: under 16 ms of our own work (`EXHAUST_FRAME_LOG=1` prints the time of each frame; `=slow` only those over budget). The UI thread never blocks on disk, the index, SQLite, a directory walk, a search, an image or PDF decode, or a layout whose cost grows with the size of a note or a vault. `ctest -R frame_budget` and `ctest -R ui_no_blocking_calls` guard this; add a case to `frame_budget` for every view that can be big, and mark a line that is safe on the UI thread with `/* ui-ok: why */`.
- **The loop.** `main.c` handles **every waiting event, then draws one frame**, and skips the frame when only an idle wake-up came. Never draw once per event: a frame waits for the screen (about 16 ms), so hundreds of mouse-motion events a second queue up. Several drag events can also arrive before one frame: a drag handler must not trust a widget's rectangle from the last layout (note what you need at the press, as `note_origin` in `src/ui/panes.c` does).
- **Work moves to threads; the UI reads snapshots.** The service thread (`src/ui/service.c`, jobs `QJ_*`, its own index reader) and the indexer return ready-made rows or buffers through the message queue (`include/exhaust_worker.h`). The UI thread fills a widget from a finished result, never computes it. A new feature adds a job, not a call.
- **Cost per frame must not depend on the size of the data.** Lay out and draw only what is on screen (editor rows, list rows, graph nodes inside the view, canvas cards, table rows). Estimate the rest (the editor does, see `vpre` and `nseg`). Cache anything derived from text or an image (shaped lines, decoded images as textures, math and diagram layouts keyed by a hash of their source) and invalidate by version, not by guessing.
- **Batch drawing.** One geometry array per frame for the graph and the canvas (`SDL_RenderGeometry` through the renderer's tessellator), no allocation per node or per edge per frame, level of detail for small shapes (fewer circle segments), culling of what is off screen, labels only above a zoom threshold.
- **Performance tests must be stable on slow CI runners.** Do not assert wall-clock frames per second. Measure the work: CPU time of a frame's own code, iterations per second of a worker, a count of operations, or the ratio to a baseline run in the same process. A limit that is just barely met on your machine is a flaky test on a runner that is five times slower (the `ui_not_blocked` failure on Windows and macOS was exactly that, in a different form). Never raise a limit to make a test pass; find the slow code, or explain in writing why the test measures the wrong thing, as ISSUES 18 does.
- **Startup and memory:** warm start under 1 second and memory under 200 MB on the performance vault (`tools/gen_vault`); the core install at most 25 MB (`tools/check_size.sh`). Every dependency and font you add costs size: check the budget when you vendor it.
- **Typing is sacred.** Nothing may delay a keystroke reaching the buffer or the journal, and no code path may lose typed text (see the hard rules).

## Dependencies
- **Vendor everything** in `third_party/`: source and headers, with each license file, and a pinned version recorded in `third_party/VERSIONS.md`. Core builds need no downloads. Commit AccessKit's Rust sources with `cargo vendor`.
- **Exception, large optional libraries (PDFium, libmpv):** vendor only their headers. Load them at run time (`dlopen` or `LoadLibrary`). Without them show "Open externally". They ship only in a separate optional add-on package, which the packaging job builds from pinned, checksummed upstream releases listed in `third_party/VERSIONS.md`.
- **[lib-Peep](https://github.com/Doggydoggywhatnow/lib-Peep)** (Unlicense, version 0.5.0) is vendored and linked statically. It is hand-written assembly for x86-64 and ARM64 with no libc or `malloc`; it plays 16-bit PCM WAV built in, and the `wav` (other bit depths and float), `wavc` (A-law, mu-law, IMA and Microsoft ADPCM) and `flac` (4 to 31 bit) codecs are separate. The pull API in `peep.h` is `peep_open`, `peep_fill`, `peep_fill32`, `peep_seek`, `peep_close`, `peep_set_gain`, `peep_set_dither` and `peep_flac_metadata`. Its `main` branch has the assembly and docs only and `peep.h` is on its `dev` branch; building it needs `nasm` (x86-64) or the GNU assembler (ARM64) in CI. Read its README and source before using it. Vendor `peep.h` from its `dev` branch, with the assembly from the same commit. The first task of sub-slice 6c-ii is a CI build of it on Linux, Windows and macOS (install NASM and the GNU assembler in CI as needed). lib-Peep is the only WAV and FLAC decoder and has no fallback: if a platform fails to build, fix it in lib-Peep. The real vendored size is still to be measured. Note what you assumed in your commit message and in the README. MP3 and OGG use dr_mp3 and stb_vorbis. Other audio and video go through libmpv.
- File watching uses dmon (single-header C) or our own inotify, ReadDirectoryChangesW and FSEvents code. Do not use efsw (C++).

## Compatibility
- **Journal and session state:** their file formats (in `docs/formats.md`) are frozen after release like every other name. A newer journal must replay in an older version or be left untouched, never discarded.
- **`docs/formats.md`** is the source of truth for every name that is frozen after release: settings keys, theme tokens, the snippet grammar, `hotkeys.ini`, `workspaces.ini`, the plugin manifest, slash commands and the Lua API. **Add a key or name to `docs/formats.md` before adding it to the code**, with its type, default and the version it first appears in. Resolve every *TODO-verify* there before implementing the item.
- **Index:** change the schema only by adding a numbered migration, only adding nullable or defaulted columns, tables and indexes; never rename, drop or retype a column. Bump the schema version and extend the compatibility test. If the cached index cannot be migrated, delete the cache and rebuild it from the notes. Never delete or alter a user's notes.
- **Settings and themes:** never rename or remove a key in `settings.ini` or a theme file. To change one, add a new key and migrate the old value on load. Keep keys Exhaust does not recognize and write them back unchanged on save, so a downgrade does not lose newer settings. Extend `tests/test_settings.c` with every change.

## Decisions already made
- Threads: the UI thread does input and drawing only and never blocks on disk, the index or layout for more than 16 ms; save and journal I/O, the file watcher, the indexer and graph layout run on worker threads that talk to the UI through a message queue; SQLite uses WAL mode with one writer connection and one reader per thread that needs one.
- Rendering: SDL_Renderer, a FreeType glyph atlas and our own tessellator for lines, curves and circles.
- Layout: Clay, vendored, on top of Exhaust's own widget tree.
- Search: SQLite FTS5 with the `trigram` tokenizer (queries under three characters fall back to a scan), PCRE2 over the candidate files, and tables for lines, blocks, sections and tasks so `line:`, `block:`, `section:`, `task:`, `task-todo:` and `task-done:` work.
- Files in `.exhaust`: `settings.ini`, `themes/*.theme`, `snippets/*.style`, `workspaces.ini`, `hotkeys.ini`, `plugins/`; their formats are in `docs/formats.md`. The index (`index.db`) is in the OS cache folder.
- Note names forbid `# ^ [ ] |` and `:`, `%%`, and Windows reserved names. Links match case-insensitively after NFC normalization.
- Saving: every edit goes to the append-only recovery journal within 200 ms, and the note file is written atomically after 1 second idle or every 5 seconds at most (`autosave_idle_ms`, `autosave_max_ms`, `journal_flush_ms`); on an outside change with unsaved edits, keep the buffer, show a conflict banner with a diff, and snapshot to file recovery first. Preserve CRLF and BOM. UTF-8 only.
- Plugins use Lua and Exhaust's own API; Obsidian plugins are not compatible.
- Math uses STIX Two Math with `hb-ot-math`. Mermaid in 0.1.0: flowchart, sequence, class, state, ER, pie and gantt.
- Spell check: own checker, `PFX`, `SFX`, `REP` and `KEY` only, no compounding, English (US) only in 0.1.
- Fonts: Atkinson Hyperlegible, Atkinson Hyperlegible Mono for code, system fonts discovered by scanning the OS font folders, no bundled emoji font.
- Date formatting uses an own formatter for Moment-style tokens.
- PDF export uses an own PDF writer (fonts subset through FreeType, deflate from miniz); exports are always light-styled.
- There is no auto-updater. A manual update check is optional and off until the user presses it.

- **Fetch first.** Other sessions push to `dev`. Run `git fetch origin dev` and compare before you say anything about the state of the project, then read `docs/PROGRESS.md`, `docs/ISSUES.md` and the newest `docs/HANDOFF-agent-v.*.md`.

## Building the slices that are left (5a to 9d)
`docs/0.1.0.md` is the spec of each sub-slice and its "Done when"; `docs/PROGRESS.md` says what is done. 28 of 61 are done (everything to 4d). Below is what exists to build on, what is not vendored yet, and the traps. **Ask the user before you start a slice.** One sub-slice at a time, tests with the code, CI green on three systems before the next, and a progress row with honest gaps.

**Patterns to follow (all exist):**
- *A new view in a tab:* a tab has `t->view` (a string; `make_content` in `src/main.c` returns the widget; the graph and canvas return a placeholder label today). The ribbon has disabled entries for graph and canvas (`rb_graph`, `rb_canvas`, `EX_ICON_GRAPH`, `EX_ICON_CANVAS`): enable them when the view exists. Feature switches are in `[features]` of `docs/formats.md`; commands are rows of the Commands table there (the code table is generated from it; `graph-view.open-graph-view`, `graph-view.open-local-graph` and `graph-view.start-graph-timelapse-animation` already exist), bound in `main.c` with `ex_commands_bind`. Update the command count in `tests/test_registry.c` if you add one.
- *Heavy data for a view:* a function in `src/index/` with a test, called from a job on the service thread (`src/ui/service.c`), returned as a snapshot. Never query the index from `src/ui/*.c` on the UI thread (`tools/check_ui_blocking.sh` fails the build of the test).
- *Panels and dialogs* talk to the application through the `ExPanelsHost` callbacks (`include/exhaust_panels.h`), never through `main.c`. Dialog callbacks run after the dialog closes: copy `arg` first.
- *Colors, sizes, fonts* are theme tokens (`docs/formats.md`, Palette and Theme tokens; the graph tokens `colors.graph_*` already exist). `ctest -R no_color_literals` fails on a literal color. *Icons* are drawn in `src/ui/icons.c` (an SVG pipeline is a future option, GitHub issue #3).
- *Session state and settings* keys go into `docs/formats.md` first (the `[graph]` session section exists; its keys do not).
- *Saving* for `.canvas` and `.base` files uses the same journal and atomic write as notes (`src/notes/`); never write a user's note except through a user action.

**5 Graph (5a to 5c).** Edges come from the `links` table (`include/exhaust_index.h`, `exhaust_links.h`); add a function that returns all nodes and edges including unresolved links, and run it on the service thread. Barnes-Hut layout on a worker thread, writing a position snapshot the UI reads without a lock (double buffer). Draw with the renderer's tessellator in one geometry array per frame; cull; hit-test with a uniform grid, not a scan; labels above a zoom threshold. Filters and groups (5b) reuse the search engine (`include/exhaust_search.h`) on the worker. Local graph depth (5c) is a breadth-first walk over the same edges. The keyboard route is a list (`ExListHandlers`) so every action works without a mouse, and every node and handle needs an accessibility node. **Perf tests (`graph_perf`, `graph_frame`) must measure CPU time per frame and layout work, not wall-clock fps** (see the efficiency section).

**6a Canvas.** JSON Canvas through **yyjson** (not vendored yet: MIT; vendor from a git tag, record it). Cards are widgets or direct draws; only visible cards are drawn; card content is hidden below the zoom threshold (setting `[canvas]`). Round-trip unknown keys unchanged. Add the canvas JSON fuzz target when the parser exists.

**6b Bases.** The expression engine (6b-i) is a standalone module: a tokenizer, a parser, an evaluator over the documented types, all 72 functions, tested against the documented examples; add the fuzz target. Base files use libyaml (vendored) and keep unknown keys. Table rows are virtualized. The map layout needs the optional network tile address; without it, a plain coordinate grid.

**6c Media.** *Images:* stb_image (public domain), a WebP decoder and an AVIF decoder (libraries not chosen yet: confirm licenses and the size cost before vendoring; the core install is limited to 25 MB), nanosvg (zlib; also what GitHub issue #3 would use). Decode on a worker, upload as a texture, cache by path and mtime. *Audio:* **lib-Peep** first (assembly, `nasm` or GNU as in CI, `peep.h` from the repo's `dev` branch; the first task of 6c-ii is the three-OS CI build, and there is no fallback decoder), dr_mp3, stb_vorbis, SDL3 output from the audio callback with no locks and no allocation. *libmpv and PDFium:* headers only, loaded at run time (`dlopen`, `LoadLibrary`); without them show "Open externally". They ship in the add-on package (9d). Decide early how CI gets a real or stub library for the `mpv_loader` and `pdf_viewer` tests. Embeds (6c-v) render through the reading view; replace the placeholders in `src/ui/reading_view.c`.

**6d Math and diagrams.** STIX Two Math (OFL; check the size) with `hb-ot-math` from the vendored HarfBuzz; Mermaid flowchart and sequence, then class, state, ER, pie and gantt, all own renderers. Cache layouts by a hash of the source; draw from the cache; never lay out in a frame.

**6e Daily notes to importers.** Date formatter for Moment-style tokens (own code, many tests); templates merge properties through `src/index/props*.c` (text surgery, never reformat); the composer reuses link-safe rename; slides split a note at `---`; the PDF writer is own code (font subsets through FreeType, deflate from miniz: vendor miniz, MIT or public domain); importers get fuzz targets and must never overwrite an existing note.

**7 Settings, hotkeys, themes, workspaces, shell.** The settings screens follow `screenshots/settings/` (28 pages) and `docs/formats.md`; the table of keys is the contract (`tests/test_settings.c`). Resolve the TODO-verify items in `formats.md` named in each row of `0.1.0.md` first. Settings pages are text-box and list screens: **add each to `tests/test_long_names.c`**. The sidebar minimum width (200 px) and the hide threshold (60 px) are constants today. Themes reload within 1 second; unknown keys are kept and written back.

**8 Vim, Lua, stubs.** Vim mode is key-sequence tests on the editor; it must add no latency to normal typing. Lua 5.4 (MIT) sandboxed (`os`, `io`, `package`, `debug`, `load` unavailable), a time limit and a memory cap, permissions per `docs/formats.md`. Stubs are present, disabled and labelled, and make no network request.

The add-on package builds PDFium and libmpv from pinned, checksummed upstream releases. Final checks: warm start, memory, size. The maintainer checklist (screen reader, IME, real hardware) is in `0.1.0.md`. Also unassigned today and easy to forget: the AccessKit OS adapters (AT-SPI, UI Automation, NSAccessibility), real pop-out windows, the Windows and macOS file watchers (they poll now), and the stub editor commands.

**Dependencies not yet vendored:** yyjson, stb_image, a WebP and an AVIF decoder, nanosvg, lib-Peep, dr_mp3, stb_vorbis, miniz, Lua, STIX Two Math, and the headers of libmpv and PDFium.
