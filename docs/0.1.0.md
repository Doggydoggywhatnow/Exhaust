# Exhaust 0.1.0: build spec

**Scope: everything in `README.md`, except its Non-goals.** Items marked *(later)* or *(optional)* are stubs: present in the interface where the README places them, clearly labeled, disabled, and documented as not yet working. Everything else must work.

Finish and commit each slice, with its tests passing and CI green on Linux, Windows and macOS, before starting the next. Each slice ends with a "done when" check. Every parser slice also adds its fuzz target (see `AGENTS.md`).

**Performance test vault:** `tools/gen_vault` (built in slice 2) creates 5,000 notes with 20,000 links. All performance numbers below refer to it, on a 2020-era laptop.

**Names:** every setting key, theme token, file grammar and API name is defined in [`formats.md`](formats.md) before it is used. The sub-slice ids (such as 1a-ii) are used in the traceability table at the end.

## 1a-i. Window and renderer
SDL3 window; SDL_Renderer with a FreeType glyph atlas; frame loop; HiDPI scaling; the CI jobs from the skeleton (hardening flags, sanitizers, size budget) stay green on all three OSes.
**Done when:** a window opens on Windows, Linux and macOS and draws text from the glyph atlas at two scales, and CI is green.

## 1a-ii. Shaping, bidi, IME and clipboard
HarfBuzz shaping with font fallback and color emoji; SheenBidi and libgrapheme for bidi and grapheme clusters; SDL3 text input for IME; clipboard.
**Done when:** automated tests shape and lay out a sample set (Latin, Arabic, Hebrew, CJK, emoji, combining marks) correctly, and IME composition and clipboard round-trip are on the maintainer checklist (they cannot run unattended).

## 1a-iii. Buffer and undo tree
Piece-table text buffer with an undo tree; cursor and selection model.
**Done when:** buffer tests pass for insert, delete, undo and redo across branches and multi-byte positions, including a randomized test against a simple reference buffer.

## 1a-iv. Widgets, Clay, theme tokens and multi-cursor
Clay layout and Exhaust's own widget tree; theme tokens (names in `formats.md`) loaded from the built-in light and dark token files, with no hard-coded colors; scalable text; multiple cursors and rectangular selection.
**Done when:** you can type, select, undo and redo multilingual text with multiple cursors in a window using a light and a dark token set, and a test fails if a color literal appears outside the token loader.

## 1b-i. Cargo vendor and CI
Vendor AccessKit with `cargo vendor`; CMake builds it offline as a static library. **CI gains the cargo setup and a libFuzzer job in this slice**, with a trivial first target that proves the job runs.
**Done when:** all three OSes build the Rust static library offline, and the libFuzzer job runs in CI.

## 1b-ii. C wrapper
A small C API in `src/a11y/` to create accessibility nodes with roles, names, focus and actions.
**Done when:** a unit test builds a tree through the wrapper and reads it back.

## 1b-iii. Tree-dump test
Every widget exposes a node. An automated test dumps the accessibility tree as text and checks roles, names and focus order against a golden file.
**Done when:** the golden-file test passes on all three OSes. (Reading the editor with a real screen reader is on the maintainer checklist under Release, not here.)

## 1b-iv. Keyboard navigation
Every widget is reachable and operable by keyboard, with a visible focus indicator.
**Done when:** a scripted key sequence visits every widget in the golden order and activates it.

## 2. Vaults and files
Open and remember vaults. **Vault manager screen**, following `screenshots/vault-manager.png`: the list of vaults with a menu for each (rename, move, remove from the list), buttons to create a vault and to open a folder as a vault, and a stub (disabled, labeled *(optional, later)*) for opening a synced vault; vault switcher button at the bottom of the file tree; vault management actions (create from an existing folder, transfer settings). File explorer on real folders: create, rename, move, delete (with the trash modes), sort (by name, modified time or created time, ascending or descending), auto-reveal, expand and collapse all. Sorting and grouping are done inside the app, stored in settings, and never rename, move or reorder anything on disk. Only create, rename, move and delete, which you do yourself, change files. the README's accepted file types; excluded files; symbolic links; file watching (dmon or own code). Workspace shell: ribbon, left and right sidebars, status bar, tabs, splits, pop-out windows, drag and drop of files and text; More-options menu items (open in default app, show in file manager, copy path). Saving, autosave and the conflict banner; CRLF, BOM and UTF-8 handling; note-name rules; the `.exhaust` folder; `settings.ini` with unknown-key preservation (keys in `formats.md`); **command registry and feature-toggle registry**; `src/platform/` (trash, cache and config folders, file associations, URI registration). Backups need no code: the README states that any backup tool works.
**`tools/gen_vault`:** a C program built by CMake. It is deterministic (fixed seed) and writes 5,000 notes with 20,000 wikilinks, plus tags, properties, aliases, headings, a few canvases and attachments. A CTest test runs it and checks the counts.
**Done when:** changing the sort order leaves every file's path and modified time on disk unchanged, with a test that checks it; you can open two vaults from the vault manager, edit and save notes in tabs, change a file outside Exhaust and see it update or get the conflict banner, delete to the trash on each OS, `tests/test_settings.c` passes, and the `gen_vault` test passes.

## 3. Markdown and live preview
Own tokenizer with source ranges; all Markdown in the README (headings, lists, tasks, quotes, code, tables, footnotes, comments, highlight, callouts, HTML subset); live preview, source mode and reading mode; folding; find and replace; rectangular selection; the default editing shortcuts listed in `formats.md` (Windows/Linux and macOS) and non-US keyboard layouts; all callout types, aliases and custom callouts; slash commands (the editor commands in the registry, with the list finished in `formats.md`); spell check; word count. **Math, Mermaid and embeds are shown as source or a placeholder here; slice 6 renders them.**
**Done when:** a sample note of every element renders correctly in all three modes, and the tokenizer and HTML-subset fuzz targets run clean for 60 seconds.

## 4a. Index, links and properties
SQLite index in the OS cache folder with migrations and the `trigram` FTS5 tokenizer, plus tables for lines, blocks, sections and tasks; wikilinks and Markdown links with suggestions; backlinks, unlinked mentions, outgoing links; aliases; tags; properties read with libyaml and edited as text, including the default `tags`, `aliases` and `cssclasses` (mapped to style classes), the date and date and time types, and vault-wide rename and change type as user actions; backlinks in the document; page preview; link-safe rename covering every case in the README; case-insensitive NFC link matching.
**Done when:** the performance vault cold-indexes in under 10 seconds, survives a deleted index, every rename case in the README has a passing test, the frontmatter fuzz target runs clean, and the index compatibility test passes.

## 4b. Search and navigation
Search with every operator in the README and saved queries; embedded `query` blocks; quick switcher; command palette; outline; bookmarks; random note; footnotes pane.
**Done when:** searches on the performance vault return in under 100 ms, and each operator has a test.

## 5. Graph view
Force-directed graph with Barnes-Hut layout, local graph, filters, groups, force sliders, display options (arrows, text fade threshold, node size, link thickness), animation, keyboard list route.
**Done when:** the performance vault's graph (5,000 nodes, 20,000 edges) runs at 30 frames per second or better, and every graph action works from the keyboard.

## 6a. Canvas
Canvas in the JSON Canvas format: notes, images, web links, text cards, groups, labeled arrows.
**Done when:** a sample canvas from the JSON Canvas spec round-trips unchanged, and the canvas JSON fuzz target runs clean.

## 6b-i. Expression engine
The expression engine as its own module: the documented types and all 72 documented functions.
**Done when:** every documented function example passes and the base-expression fuzz target runs clean for 60 seconds.

## 6b-ii. Base core
Read and write `.base` files with libyaml (keeping unknown keys); filters, sorting, grouping, summaries (built-in and custom), formulas, the `this` object, the `note.`, `file.` and `formula.` namespaces, limit, copy to clipboard, export CSV, and embedding as a code block.
**Done when:** a sample `.base` file filters, sorts, groups and summarizes as documented and round-trips with unknown keys kept.

## 6b-iii. Layouts
Table, list, cards, kanban and map layouts with their settings (row height, card size and image property, kanban columns, list markers and separators); the map needs the optional tile address and falls back to a plain coordinate plot.
**Done when:** each layout renders the sample base, and the map layout shows the coordinate plot with no network access.

## 6c-i. Images and SVG
Images through stb_image with WebP and AVIF decoders, and SVG through nanosvg; image sizes (`|640x480`, `|100`); external image URLs are optional, off by default and show a placeholder.
**Done when:** a note with each image type and size syntax renders, and with external URLs off a placeholder shows and a test with the network blocked sees no connection attempt.

## 6c-ii. Audio
Audio embeds with lib-Peep (WAV and FLAC), dr_mp3 and stb_vorbis, and SDL3 output; play, pause, seek.
**Done when:** WAV, FLAC, MP3 and OGG files play, seek and stop in an embed, and the decoders pass tests against reference samples.

## 6c-iii. libmpv loader
libmpv loaded at run time (headers only vendored) for video and the other audio formats; "Open externally" when it is missing.
**Done when:** with libmpv present a video embed plays; without it the embed shows "Open externally" and nothing fails.

## 6c-iv. PDFium loader and viewer
PDFium loaded at run time; a PDF viewer with a table of contents, fit width and height, in-PDF search (match case, highlight all), copy text, and links to a selection such as `[[f.pdf#page=1&selection=...]]`; "Open externally" when PDFium is missing.
**Done when:** a sample PDF opens with each viewer feature working, and without PDFium it shows "Open externally".

## 6c-v. Embed syntax
Embeds of notes, headings, blocks, lists and canvases; PDF `#page=N&height=H`; the external image URL option.
**Done when:** every embed form in the README renders in a sample vault.

## 6d. Math and diagrams
LaTeX-subset math with STIX Two Math and `hb-ot-math`; Mermaid flowchart, sequence, class, state, ER, pie and gantt.
**Done when:** a sample note with every supported equation feature and diagram type renders correctly.

## 6e. Structure features and import
Daily notes, templates and the Moment-style date formatter; unique note creator; note composer; slides; format converter that migrates old frontmatter vault-wide (`alias` to `aliases`, `tag` to `tags`, `cssclass` to `cssclasses`) only on user command with a backup warning; template property merging; note composer template file; **export to PDF** (own PDF writer, options page size, landscape, margin, downscale and file name as title, always light-styled, from the command palette and the More-options menu); import tools (Markdown, plain text, HTML, CSV, Textbundle, importer templates, and the other apps' importers as disabled *(later)* entries); audio recorder, command line and URI scheme as stubs.
**Done when:** each feature has a test or a documented manual check, and the importer fuzz targets run clean.

## 7. Settings, hotkeys, themes, workspace
Settings screen with every page and option the README lists (General, Appearance, Interface, Editor, Files and links, Hotkeys, Keychain stub, Built-in features, Plugins stub, and one page per feature with options), following the pages in `screenshots/settings/`, `screenshots/hotkeys.png` and `screenshots/vault-manager.png`; the manual update check as an optional stub, with no auto-updater; every command bindable with conflict display (`hotkeys.ini`); themes and style snippets as described in the README, with live reload, contrast warnings and unknown-key preservation (grammars in `formats.md`); workspaces (`workspaces.ini`); file recovery snapshots; ribbon configuration; high contrast; interface zoom; the default size of a new window.
**Done when:** switching themes and editing a theme file update the app live, every key in `formats.md` is read and written by Settings, and the theme and settings compatibility tests pass.

## 8. Vim mode, plugins and optional features
Vim mode; Lua plugin API with permissions; web clipper extension (`extras/clipper/`), community directory, languages, sync, shared vaults and publish as labeled stubs.
**Done when:** a sample plugin adds a command and a pane and cannot touch anything it did not declare, and Vim mode passes its key-sequence tests.

## 9. Packaging
CI produces a zip (Windows), AppImage (Linux) and dmg (macOS) with file association and URI registration, plus the separate optional add-on package with PDFium and libmpv. Run the final performance and size checks.
**Done when:** on the performance vault, warm start takes under 1 second and memory use stays under 200 MB; the core install is at most 25 MB; each package installs and opens a vault on its OS.

## Release
Update the README (dependency licenses confirmed, UI decisions recorded), tag `v0.1.0` on `dev`, and open a pull request to `main`.

### Maintainer checklist
Things that cannot run unattended in CI. Do them before tagging:
- Read the editor with a real screen reader on at least one OS.
- Type with an input method (IME) in the editor on each OS, and copy and paste between Exhaust and another app.
- Run the performance vault checks on real hardware.
- Open a vault from each package on its OS.
