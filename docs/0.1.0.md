# Exhaust 0.1.0: build spec

**Scope: everything in `README.md`, except its Non-goals.** Items marked *(later)* or *(optional)* are stubs: present in the interface where the README places them, clearly labeled, disabled, and documented as not yet working. Everything else must work.

Finish and commit each slice, with its tests passing and CI green on Linux, Windows and macOS, before starting the next. Each slice ends with a "done when" check. Every parser slice also adds its fuzz target (see `AGENTS.md`).

**Performance test vault:** `tools/gen_vault` creates 5,000 notes with 20,000 links. All performance numbers below refer to it, on a 2020-era laptop.

## 1a. Window, text, buffer and theme tokens
SDL3 window; SDL_Renderer with FreeType glyph atlas; Clay layout and own widget tree; HarfBuzz text with font fallback, bidi and grapheme handling; piece-table buffer with undo tree; cursor, selection, IME, clipboard, multiple cursors; **theme tokens loaded from the start, no hard-coded colors**; scalable text.
**Done when:** you can type, select, undo and redo multilingual text in a window with a light and a dark token set, and buffer tests pass.

## 1b. Accessibility tree
AccessKit bridge in `src/a11y/` (vendored Rust sources, built offline); every widget exposes a node; keyboard navigation.
**Done when:** an automated test dumps the accessibility tree and checks roles, names and focus order, and a screen reader reads the editor by hand on at least one OS.

## 2. Vaults and files
Open and remember vaults; vault switcher button; file explorer on real folders; create, rename, move, delete (with the trash modes), sort; the README's accepted file types; excluded files; symbolic links; file watching (dmon or own code); tabs, splits, pop-out windows; saving, autosave and the conflict banner; CRLF, BOM and UTF-8 handling; note-name rules; `.exhaust` folder; `settings.ini` with unknown-key preservation; **command registry and feature-toggle registry**; `src/platform/` (trash, cache and config folders, file associations, URI registration).
Vault management (rename, move, remove, create from an existing folder, transfer settings); file explorer auto-reveal and expand/collapse all; More-options menu items (open in default app, show in file manager, copy path).
**Done when:** you can open two vaults, edit and save notes in tabs, change a file outside Exhaust and see it update or get the conflict banner, delete to the trash on each OS, and `tests/test_settings.c` passes.

## 3. Markdown and live preview
Own tokenizer with source ranges; all Markdown in the README (headings, lists, tasks, quotes, code, tables, footnotes, comments, highlight, callouts, HTML subset); live preview, source mode and reading mode; folding; find and replace; rectangular selection; the default shortcut tables from the Help page "Editing shortcuts" for Windows/Linux and macOS, and non-US keyboard layouts; all callout types, aliases and custom callouts; editing shortcuts; slash commands; spell check; word count. **Math, Mermaid and embeds are shown as source or a placeholder here; slice 6 renders them.**
**Done when:** a sample note of every element renders correctly in all three modes, and the tokenizer and HTML-subset fuzz targets run clean for 60 seconds.

## 4a. Index, links and properties
SQLite index in the OS cache folder with migrations and the `trigram` FTS5 tokenizer, plus tables for lines, blocks, sections and tasks; wikilinks and Markdown links with suggestions; backlinks, unlinked mentions, outgoing links; aliases; tags; properties read with libyaml and edited as text, including the default `tags`, `aliases` and `cssclasses` (mapped to style classes), the date and date and time types, and vault-wide rename and change type as user actions; backlinks in the document; page preview; link-safe rename covering every case in the README; case-insensitive NFC link matching.
**Done when:** the performance vault cold-indexes in under 10 seconds, survives a deleted index, every rename case in the README has a passing test, the frontmatter fuzz target runs clean, and the index compatibility test passes.

## 4b. Search and navigation
Search with every operator in the README and saved queries; embedded `query` blocks; quick switcher; command palette; outline; bookmarks; random note; footnotes pane.
**Done when:** searches on the performance vault return in under 100 ms, and each operator has a test.

## 5. Graph view
Force-directed graph with Barnes-Hut layout, local graph, filters, groups, force sliders, display options (arrows, text fade threshold, node size, link thickness), animation, keyboard list route.
**Done when:** the performance vault's graph (5,000 nodes, 20,000 edges) runs at 30 frames per second or better, and every graph action works from the keyboard.

## 6a. Canvas
Canvas in the JSON Canvas format: notes, images, web links, text cards, groups, labeled arrows.
**Done when:** a sample canvas from the JSON Canvas spec round-trips unchanged, and the canvas JSON fuzz target runs clean.

## 6b. Bases and the expression engine
The expression engine as its own module: types and all 72 documented functions, tested against the examples in the docs. Bases with grouping, summaries (built-in and custom), the `this` object, the `note.`, `file.` and `formula.` namespaces, limit, copy to clipboard, export CSV, embedding as a code block, per-layout settings (row height, card size and image property, kanban columns, list markers and separators), and table, list, cards, kanban and map layouts (map needs the optional tile address, with a coordinate-plot fallback); `.base` files and embedded bases.
**Done when:** every documented function example passes, and the base-expression fuzz target runs clean.

## 6c. Embeds, media, PDF and SVG
Embeds of notes, headings, blocks, lists and canvases, with image sizes (`|640x480`, `|100`), PDF `#page=N&height=H` and external image URLs (optional, placeholder when off); images including SVG (nanosvg); audio with lib-Peep, dr_mp3 and stb_vorbis; video and other audio through libmpv loaded at run time; PDFs through PDFium loaded at run time, with a PDF viewer (table of contents, fit width and height, in-PDF search with match case and highlight all, copy text, links to a selection such as `[[f.pdf#page=1&selection=...]]`); "Open externally" when a library is missing.
**Done when:** a vault with one of each accepted file type embeds correctly, and removing the optional libraries shows "Open externally" instead of failing.

## 6d. Math and diagrams
LaTeX-subset math with STIX Two Math and `hb-ot-math`; Mermaid flowchart, sequence, class, state, ER, pie and gantt.
**Done when:** a sample note with every supported equation feature and diagram type renders correctly.

## 6e. Structure features and import
Daily notes, templates and the Moment-style date formatter; unique note creator; note composer; slides; format converter that migrates old frontmatter vault-wide (`alias` to `aliases`, `tag` to `tags`, `cssclass` to `cssclasses`) only on user command with a backup warning; template property merging; note composer template file; **export to PDF** (own PDF writer, options page size, landscape, margin, downscale and file name as title, always light-styled, from the command palette and the More-options menu); import tools (Markdown, plain text, HTML, CSV, Textbundle, importer templates, and the other apps' importers as disabled *(later)* entries); audio recorder, command line and URI scheme as stubs.
**Done when:** each feature has a test or a documented manual check, and the importer fuzz targets run clean.

## 7. Settings, hotkeys, themes, workspace
Settings screen with every item the README lists (including the appearance, general and interface items added from the docs, and the manual update check, with no auto-updater), following `screenshots/settings.png`; every command bindable with conflict display; themes and style snippets as described in the README, with live reload, contrast warnings and unknown-key preservation; workspaces; file recovery snapshots; status bar; ribbon; high contrast; interface zoom.
**Done when:** switching themes and editing a theme file update the app live, and the theme and settings compatibility tests pass.

## 8. Vim mode, plugins and optional features
Vim mode; Lua plugin API with permissions; web clipper extension (`extras/clipper/`), community directory, languages, sync, shared vaults and publish as labeled stubs.
**Done when:** a sample plugin adds a command and a pane and cannot touch anything it did not declare, and Vim mode passes its key-sequence tests.

## 9. Packaging
CI produces a zip (Windows), AppImage (Linux) and dmg (macOS) with file association and URI registration, plus the separate optional add-on package with PDFium and libmpv. Run the final performance and size checks.
**Done when:** on the performance vault, warm start takes under 1 second and memory use stays under 200 MB; the core install is at most 25 MB; each package installs and opens a vault on its OS.

## Release
Update the README (dependency licenses confirmed, UI decisions recorded), tag `v0.1.0` on `dev`, and open a pull request to `main`.
