# Exhaust 0.1.0: build spec

**Scope: everything in `README.md`, except its Non-goals.** Items marked *(later)* or *(optional)* are stubs: present in the interface where the README places them, clearly labeled, disabled, and documented as not yet working. Everything else must work.

Finish and commit each sub-slice, with its tests passing and CI green on Linux, Windows and macOS, before starting the next. Each sub-slice has a scope, the sub-slices it depends on, and one "done when" check that names a test or a command. Every parser sub-slice also adds its fuzz target (see `AGENTS.md`). A sub-slice that adds a dependency also updates `.github/workflows/ci.yml` for Linux, Windows and macOS.

**Performance test vault:** `tools/gen_vault` (built in 2e) creates 5,000 notes with 20,000 links. All performance numbers below refer to it, on a 2020-era laptop.

**Names:** every setting key, theme token, file grammar and API name is defined in [`formats.md`](formats.md) before it is used. The sub-slice ids (such as 2a) are used in the traceability table at the end.

## 1a-i. Window, renderer and text atlas

Scope: SDL3 window; SDL_Renderer; FreeType glyph atlas; scalable text and HiDPI scaling. The skeleton's CI jobs (hardening flags, sanitizers, size budget) stay green on all three OSes.

Depends on: none (the skeleton)

**Done when:** `ctest -R renderer_smoke` passes on Linux, Windows and macOS in CI: with SDL's dummy video driver it renders glyphs from the atlas at 1x and 2x scale and matches stored images within a set tolerance.

## 1a-ii. Shaping, fonts, bidi, IME and clipboard

Scope: HarfBuzz shaping with font fallback and color emoji; system font scan of the OS font folders; SheenBidi and libgrapheme for bidi and grapheme clusters; SDL3 text input (IME); clipboard.

Depends on: 1a-i

**Done when:** `ctest -R shaping` passes: sample strings (Latin, Arabic, Hebrew, CJK, emoji, combining marks) give the expected glyph runs, bidi order and cluster boundaries, and the font scan finds at least one font. IME and clipboard cannot run unattended and are on the maintainer checklist.

## 1a-iii. Buffer, undo tree and selections

Scope: Piece-table text buffer; undo tree; cursor, selection and multiple-cursor model.

Depends on: none

**Done when:** `ctest -R buffer` passes, including a randomized test (fixed seed, 100,000 operations) against a simple reference buffer.

## 1a-iv. Layout, widgets, theme tokens and editor widget

Scope: Clay layout and Exhaust's own widget tree; theme tokens (names in `formats.md`) loaded from the built-in light and dark token files, using the values in the Palette table in `formats.md`, with no hard-coded colors; an editor widget on the buffer; multi-cursor input.

Depends on: 1a-i, 1a-ii, 1a-iii

**Done when:** `ctest -R editor_widget` passes: scripted input types, selects, undoes and redoes multilingual text with several cursors under both token sets, and `ctest -R no_color_literals` fails if a color literal appears outside the token loader.

## 1b-i. AccessKit vendoring and CI

Scope: Vendor AccessKit with `cargo vendor`; CMake builds it offline as a static library; cargo is set up in CI on Linux, Windows and macOS; CI gains a libFuzzer job with a trivial first target.

Depends on: 1a-i

**Done when:** The CI job `a11y-build` builds the AccessKit static library with `cargo build --offline` on all three OSes, and the libFuzzer job runs its trivial target for 10 seconds without a crash.

## 1b-ii. Accessibility C wrapper

Scope: A small C API in `src/a11y/` to create accessibility nodes with roles, names, focus and actions; one node per widget.

Depends on: 1b-i, 1a-iv

**Done when:** `ctest -R a11y_wrapper` passes: a tree built through the wrapper reads back with the same roles, names and parents, and every widget type creates exactly one node.

## 1b-iii. Accessibility-tree dump test

Scope: An automated test that dumps the accessibility tree as text and checks roles, names and focus order.

Depends on: 1b-ii

**Done when:** `ctest -R a11y_dump` passes on all three OSes, comparing the dump of the sample window with a golden file. Reading with a real screen reader is on the maintainer checklist.

## 1b-iv. Keyboard navigation

Scope: Every widget is reachable and operable by keyboard, with a visible focus indicator.

Depends on: 1b-iii

**Done when:** `ctest -R keyboard_nav` passes: a scripted Tab sequence visits every widget in the golden focus order and Enter or Space activates each one.

## 2a. Vaults, file tree and file actions

Scope: Open and remember vaults; file explorer on the vault's real folders; in-app sorting by name, modified time or created time, ascending or descending. Sorting and grouping are done inside the app, stored in settings, and never rename, move or reorder anything on disk. Only create, rename, move and delete, which you do yourself, change files. Create, rename, move and delete with the trash modes (the file-trash functions for each OS in `src/platform/`); auto-reveal, expand and collapse all; the README's accepted file types; excluded files; symbolic links; the More-options menu items (open in default app, show in file manager, copy path). Backups need no code: the README states that any backup tool works.

Depends on: 1a-iv

**Done when:** `ctest -R vault_tree` passes: create, rename, move and delete work on a temporary vault in each trash mode, and changing the sort order leaves every file's path and modified time on disk unchanged.

## 2b. File watching, saving and note names

Scope: File watching (dmon or own code); autosave after a short idle; the conflict banner with a diff, keeping the editor's text when a file changes on disk during unsaved edits; CRLF, BOM and UTF-8 handling; note-name rules.

Depends on: 2a

**Done when:** `ctest -R file_safety` passes: an outside edit updates the open buffer or raises the conflict banner when edits are unsaved, CRLF and a BOM survive a save byte for byte, invalid UTF-8 is refused, and every forbidden note name is rejected.

## 2c. Tabs, splits, sidebars and drag and drop

Scope: Tabs, splits, pop-out windows; left and right sidebars; drag and drop of files and text.

Depends on: 2a, 1a-iv

**Done when:** `ctest -R workspace_layout` passes: tabs, splits, a pop-out window and both sidebars can be created, moved and closed by scripted input, and dropped files and text reach the right widget.

## 2d. Settings file, registries and platform layer

Scope: The `.exhaust` folder; `settings.ini` with unknown-key preservation (keys in `formats.md`); the command registry and the feature-toggle registry; the rest of `src/platform/` (cache and config folders, file associations, URI registration).

Depends on: 2a

**Done when:** `ctest -R "settings|registry"` passes (including `tests/test_settings.c`): unknown keys survive load and save, and commands and feature toggles register and can be enabled and disabled.

## 2e. Vault manager and `tools/gen_vault`

Scope: The vault manager screen, following `screenshots/vault-manager.png`: the list of vaults with a menu for each (rename, move, remove from the list), buttons to create a vault and to open a folder as a vault, and a stub (disabled, labeled *(optional, later)*) for opening a synced vault; the vault switcher button at the bottom of the file tree; vault management (create from an existing folder, transfer settings); folders are chosen with the OS's native folder-picker dialog (SDL3 provides one on all three OSes), and on first launch with no known vault the vault manager is shown. `tools/gen_vault`: a C program built by CMake, deterministic (fixed seed), writing 5,000 notes with 20,000 wikilinks, plus tags, properties, aliases, headings, a few canvases and attachments.

Depends on: 2a, 2c, 2d

**Done when:** `ctest -R "vault_manager|gen_vault"` passes: `gen_vault` run twice with the same seed writes identical output with 5,000 notes and 20,000 wikilinks, and the vault manager test (folder picker mocked) creates, opens, renames and removes a vault from its list.

## 3a. Tokenizer, callouts and HTML subset

Scope: Own tokenizer with source ranges for all Markdown in the README (headings, lists, tasks, quotes, code, tables, footnotes, comments, highlight); all callout types, their aliases and custom callouts; the HTML subset; the tokenizer and HTML-subset fuzz targets.

Depends on: 1a-iii

**Done when:** `ctest -R tokenizer` passes on a sample note containing every element, and the tokenizer and HTML-subset fuzz targets run for 60 seconds without a crash.

## 3b. Source mode and live preview

Scope: Source mode and live preview in the editor widget; math, Mermaid and embeds are shown as source or a placeholder until 6c to 6d render them.

Depends on: 3a, 1a-iv

**Done when:** `ctest -R live_preview` passes: for the sample note, live preview hides syntax away from the cursor and shows it under the cursor, and source mode shows the text unchanged.

## 3c. Reading mode and folding

Scope: Reading mode (md4c); folding of headings and lists.

Depends on: 3a

**Done when:** `ctest -R reading_mode` passes: the reading-mode output of the sample note matches a golden file, and folding collapses and expands the right ranges.

## 3d. Find, rectangular selection, shortcuts and slash commands

Scope: Find and replace with regular expressions (PCRE2); rectangular selection; the default editing shortcuts listed in `formats.md` (Windows/Linux and macOS) and non-US keyboard layouts; slash commands (the editor commands in the registry, with the list finished in `formats.md`).

Depends on: 1a-iii, 1a-iv, 2d

**Done when:** `ctest -R editing` passes: plain and regex find and replace on a sample, rectangular selection on a column, every default shortcut in `formats.md` maps to its action, and the slash menu lists the registered editor commands with fuzzy matching.

## 3e. Spell check and word count

Scope: Spell check with Exhaust's own checker (Hunspell-format word lists, `PFX`, `SFX`, `REP` and `KEY` only, English (US) included); word count.

Depends on: 1a-iv

**Done when:** `ctest -R spellcheck` passes: known words pass, misspellings are flagged with suggestions from a sample list, `PFX`, `SFX`, `REP` and `KEY` rules are each covered, and the word count matches a known sample.

## 4a-i. Index schema and indexer

Scope: SQLite index in the OS cache folder, keyed by vault, with numbered migrations and the `trigram` FTS5 tokenizer, plus tables for lines, blocks, sections and tasks; the indexer; rebuild from the notes.

Depends on: 2b, 3a

**Done when:** `ctest -R index` passes: the performance vault cold-indexes in under 10 seconds, a deleted index rebuilds to identical contents, and the index compatibility test (migration from every earlier schema version) passes.

## 4a-ii. Links, backlinks and page preview

Scope: Wikilinks and Markdown links with suggestions; case-insensitive NFC link matching; backlinks (panel and in the document), unlinked mentions, outgoing links; aliases; page preview.

Depends on: 4a-i, 3a

**Done when:** `ctest -R links` passes: on a sample vault, link resolution (case-insensitive, NFC), alias targets, backlinks, unlinked mentions and outgoing links match a golden table, including unresolved links.

## 4a-iii. Tags and properties

Scope: Tags, including nested tags; properties read with libyaml and edited as text; the default `tags`, `aliases` and `cssclasses` (mapped to style classes); the date and date and time types; vault-wide rename and change type as user actions; the frontmatter fuzz target.

Depends on: 4a-i

**Done when:** `ctest -R properties` passes: edits change only the edited lines and leave every other byte as it was, rename and change type work across a sample vault, and the frontmatter fuzz target runs for 60 seconds without a crash.

## 4a-iv. Link-safe rename

Scope: Link-safe rename covering wikilinks, embeds, Markdown links (URL-encoded and relative), links inside properties, and `#heading` and `#^block` references. The `.canvas`, `.base` and bookmark cases get their tests in 6a, 6b-ii and 4b-iv.

Depends on: 4a-ii, 4a-iii

**Done when:** `ctest -R rename` passes with one test for each case listed in Scope.

## 4b-i. Search engine and operators

Scope: The search engine with every operator in the README, regular expressions, `OR`, `-`, parentheses and quotes, property filters, and sorted results with context.

Depends on: 4a-i

**Done when:** `ctest -R search` passes with one test per operator, and `ctest -R search_perf` shows a search over the performance vault returning in under 100 ms.

## Release
Update the README (dependency licenses confirmed, UI decisions recorded), tag `v0.1.0` on `dev`, and open a pull request to `main`.

### Maintainer checklist
Things that cannot run unattended in CI. Do them before tagging:
- Read the editor with a real screen reader on at least one OS.
- Type with an input method (IME) in the editor on each OS, and copy and paste between Exhaust and another app.
- Run the performance vault checks on real hardware.
- Open a vault from each package on its OS.
