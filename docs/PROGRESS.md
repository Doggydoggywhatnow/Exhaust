# Exhaust 0.1.0: progress

Read this first when resuming. It tracks the sub-slices of [`0.1.0.md`](0.1.0.md) in build order. Update it in the same commit as each sub-slice.

**Status values:** `not started`, `in progress`, `done` (tests pass locally and CI is green on Linux, Windows and macOS), `done, CI pending` (committed and pushed, CI not yet confirmed green on all three).

**Rules:** one sub-slice at a time; commit and push to `dev` after each; CI green on all three OSes before the next; never push to `main`; never skip, loosen or delete a test. **Checkpoints, stop and report for review:** after 1b-iv (first typing build), after 3b (first live-preview build), after 4b-iv (first usable build).

## Responsiveness (after 4d)

Added after hand-testing, so that every later feature stays inside the 16 ms rule: **`ctest -R frame_budget`** (a 6000-line note: typing, Enter, Page Down and resizing, input handlers under 16 ms and frames under 60 ms at the 95th percentile on the software renderer; ten times that under sanitizers; `FRAME_BUDGET_VERBOSE=1` names slow steps), **`ctest -R ui_no_blocking_calls`** (`tools/check_ui_blocking.sh` fails if code the interface thread runs calls a search, an index sync, a directory walk, a sleep or SQLite; a line that is safe says `ui-ok`), the main loop handles every waiting event before one frame and **skips the frame when only an idle wake-up came** (the caret blink and workspace changes still draw), `EXHAUST_FRAME_LOG=1` (every frame) or `=slow` (frames over 16 ms) prints frame times on stderr, and the lists, tree and editor already draw only the rows on screen. Not done because they would change the renderer: caching the sidebars and tabs as textures, and drawing only the changed rectangles. **Rule for every later sub-slice:** a new view or panel gets its own case in `frame_budget` when it can be big (the graph in 5, the canvas in 6, bases in 8). **Since agent v.04:** `frame_budget` ends every frame with `SDL_FlushRenderer`, so a frame is charged for its own drawing (before, queued draw commands piled up and one frame paid for them all: ISSUES 9). A default `cmake -S . -B build` has **no optimization**; time things in `-DCMAKE_BUILD_TYPE=Release` (`build-rel`), where the same frames take about a third as long.

**Since agent v.05:** the graph has its own timing tests: `graph_perf` (the layout: work counts, accuracy, settling, torn reads) and `graph_frame` (a frame of our own code at three zoom levels with 5,000 nodes and 20,000 edges, handlers while the layout runs, no allocation in a steady frame, triangles under 120,000). `graph_frame` limits our code and the triangle count and **prints but does not limit SDL's software rasterizer**, which takes 0.1 to 0.5 seconds a frame on that many triangles in a build without optimization; do not copy `frame_budget`'s flush-and-charge rule for a view with a great many triangles, and do cut long lines at the screen edge (`ex_geom_set_cull`). While `ex_graphmodel_animating` the main loop wakes every 16 ms instead of every 100 ms.
