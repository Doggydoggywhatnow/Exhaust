# Exhaust: issues

Problems noticed while building and testing, in the order they were noticed. Add an entry as soon as something is seen, with what was observed, who or what noticed it, and (when known) the cause. Move an entry to **Fixed** with the commit when it is done. A fix does not need its own sub-slice; it can go in with the sub-slice being built, and is then named in that row of [`PROGRESS.md`](PROGRESS.md).

Status: `open`, `diagnosed` (cause found, not fixed), `fixed`.

## Fixed

Fixed together in sub-slice 4d and after (CI and a hand test still to confirm): 1, 2, 3 (a859a4a), 5 (a859a4a), 4, 6, 7 and 8 (this commit).

- **4, Enter:** measured with `frame_budget`: Enter in the middle of a 6000-line note takes about 1 ms in the handler and a frame 5 to 7 ms. It was the event backlog (1).
- **6, missing notes:** Ctrl (Command on a Mac) and click on a link in the editor, or in reading mode, creates the note it names and opens it (written when something is typed). A plain click in reading mode only says that the note does not exist; nothing is created by itself.
- **7, ribbon:** drawn icons (quick switcher, graph and canvas as disabled stubs labelled "not available yet", command palette; at the bottom the mode, left and right sidebar and light and dark switches), pressed state for the sidebar and mode buttons, icons centred. Ribbon configuration is sub-slice 7f.
- **8, inline title:** a large bold title between the tab strip and the text, the note's name; Enter renames the file through the link-safe flow (a name that is not valid or is taken is refused with a message and the old name comes back, Escape undoes, Down goes to the text); a new note starts as "Untitled" with the title focused, and naming it before typing makes the file with that name. `[editor] inline_title` hides it. Headings in the text use Obsidian's sizes.
