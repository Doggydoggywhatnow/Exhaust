# Exhaust tests

This file describes how Exhaust is tested and lists tests to add over time.

**The first release does not need most of this.** For 0.1.0 the only required tests are:

1. The "Done when" check of each sub-slice in `docs/0.1.0.md` (every `ctest -R ...` name, fuzz target and CI job named there).
2. The minimum in `AGENTS.md` (buffer and undo tree, tokenizer, link and property parsing, index and search, link-safe rename, Bases expressions, settings and theme loading, compatibility tests).

Everything in the **Backlog** below is optional for 0.1.0. A later agent picks items from it. When you add one, change `[ ]` to `[x]` and write the ctest name after it. Never delete an item; if it no longer applies, mark it `[-]` with the reason.

## Conventions

- **Language and runner.** Tests are C11 programs registered with CMake and run by `ctest`. There is no test framework dependency: use the small header `tests/exhaust_test.h` (`EXPECT(cond)`, `EXPECT_EQ_INT`, `EXPECT_EQ_STR`, `EXPECT_EQ_BYTES`, and a summary that returns non-zero on failure). One executable per area: `tests/test_<area>.c`.
- **Registering.** CMake helper `exhaust_add_test(<name> SOURCES ... LABELS ...)`. The ctest name is lower snake case and is the name used in `docs/0.1.0.md`.

  ```c
  #include "exhaust_test.h"
  #include "exhaust.h"

  int main(void) {
      EXPECT_EQ_STR(exhaust_version(), "0.1.0");
      return exhaust_test_done();
  }
  ```

- **Labels.** `unit` (pure logic), `integration` (files, index, several modules), `ui` (scripted input and dumps), `perf`, `fuzz`, `compat`, `manual` (documented, not run by CI).
- **Deterministic.** Fixed random seeds, no network, no real time (use the injected clock), no writes outside a temporary directory made with `mkdtemp` and removed at the end. A test that needs a display uses SDL's dummy video driver.
- **Fixtures.** Small text files in `tests/fixtures/`. Larger or random data is generated by `tools/` programs (for example `tools/gen_vault`), never committed. Do not commit anything copied from another app, and record the license of any third-party test data in `third_party/VERSIONS.md`.
- **Golden files.** Expected output lives in `tests/golden/`. Regenerate with `EXHAUST_UPDATE_GOLDEN=1 ctest -R <name>` and review the diff by hand. Goldens contain no timestamps, absolute paths or machine-specific values.
- **Fuzz targets.** In `tests/fuzz/`, built with clang `-fsanitize=fuzzer,address,undefined`. Each parser takes `(const char *buf, size_t len)` and has no global state. Corpus seeds go in `tests/fuzz/corpus/<target>/`. CI runs each target for 60 seconds.
- **Performance.** Prefer relative checks (for example "at least 10 times faster than the full path") over absolute times, because CI machines vary. Absolute budgets from `docs/0.1.0.md` run in the `perf` label on one OS.
- **No weakening.** Never skip, disable, loosen or delete a failing test to make CI green. Fix the code, or ask the maintainer.

## Hooks the 0.1.0 code should include

These are cheap to add while building and expensive to retrofit. They are what make the backlog possible. Add each in the sub-slice shown.

| Hook | Why | Sub-slice |
| --- | --- | --- |
| All file reads and writes go through one module in `src/platform/` (`fs`), with a test mode that records every write and can inject failures (disk full, permission denied, rename failure) | Lets tests prove "notes are only written by user actions", atomic saves and write-failure handling | 2a |
| One clock function, one random-number function, both replaceable in tests | Deterministic snapshots, autosave timers, unique note names | 1a-i |
| All network access goes through one module that refuses everything by default and logs attempts | Lets one test prove the app makes no requests unless an optional feature is on | 2d |
| Every command is callable by id from a test (`exhaust_run_command("editor:toggle-bold")`) | Scripted UI tests without simulating clicks | 2d |
| A UI test driver: inject key, mouse and text events; dump the draw list; dump the accessibility tree | `ui` tests, accessibility goldens, screenshot-free layout checks | 1a-iv, 1b-iii |
| Parsers are pure functions of `(buf, len)` | Fuzzing and property tests | each parser slice |
| Index schema version and every migration are numbered and loadable from fixtures | Compatibility tests | 4a-i |

## CI tiers

- **Every push, all three OSes:** labels `unit`, `integration`, `ui`, `compat`.
- **Every push, Linux:** ASan and UBSan build running everything above; each fuzz target for 60 seconds; the size check.
- **Nightly, one OS:** the `perf` label, and 10-minute fuzz runs per target.
- **Maintainer, before a release:** the `manual` checklist at the end of this file.

## Backlog

Priority: **P1** add soon after 0.1.0 (cheap and protects users), **P2** add as the feature matures, **P3** nice to have.

### Safety of users' notes (highest value)

- [ ] **T-SAFE-01 (P1)** Write invariant: run a scripted session (open, browse, search, change settings, sort, run the graph) on a fixture vault with the write log on, and assert no note file's bytes or modified time changed.
- [ ] **T-SAFE-02 (P1)** Never reformat: for a table of frontmatter files (odd indentation, comments, quotes, CRLF, BOM, duplicate-looking keys, unknown keys), change one property and assert every other byte is identical.
- [ ] **T-SAFE-03 (P1)** Atomic write: inject a failure at each step (temp file write, flush, rename) and assert the original note is intact and the text survives in the journal.
- [ ] **T-SAFE-04 (P1)** Crash safety: type in a test harness, `kill -9` after 1 second, relaunch, assert all text is restored (uses the recovery journal in `docs/formats.md`; `ctest -R autosave_crash` in sub-slice 2b is the 0.1.0 version of this test).
- [ ] **T-SAFE-05 (P2)** Disk full and read-only folder: assert the text stays in the journal and a persistent error names the file.
- [ ] **T-SAFE-06 (P2)** Link-safe rename never touches files that don't link to the renamed note, and a failure halfway can be fully undone.
- [ ] **T-SAFE-07 (P2)** Import never overwrites an existing note; a name clash gets a numbered name.
- [ ] **T-SAFE-08 (P2)** Deleting an index, session state or cache never deletes or alters notes.

### Privacy and security

- [ ] **T-PRIV-01 (P1)** With the network module in refuse-and-log mode, run the full scripted session and assert zero attempts.
- [ ] **T-PRIV-02 (P1)** On Linux, run the app inside `unshare -n` (no network at all) and assert it starts, opens a vault and exits normally.
- [ ] **T-PRIV-03 (P2)** Each *(optional)* feature (map tiles, external images, update check, community directory) makes a request only after its switch is on, and only to the address the user set.
- [ ] **T-SEC-01 (P1)** Path traversal: links, embeds, canvas file nodes, base `file` references and importers pointing at `../../outside` or an absolute path never read or write outside the vault.
- [ ] **T-SEC-02 (P1)** Archive safety: Textbundle and any zip input with `../` names or absolute names is rejected (zip-slip).
- [ ] **T-SEC-03 (P2)** Symlink escape: a symlink inside the vault that points outside is followed for reading only if the setting allows it, and loops are detected.
- [ ] **T-SEC-04 (P2)** Plugin sandbox: from Lua, `os`, `io`, `package`, `debug`, `load` and `require` of native modules are unavailable; a plugin without a permission gets an error for each guarded call; a runaway loop is stopped by the time limit; memory use is capped.
- [ ] **T-SEC-05 (P2)** HTML subset: scripts, event attributes, `javascript:` URLs, `<iframe>`, `<object>` and remote `style` loads are dropped or shown as text.
- [ ] **T-SEC-06 (P3)** Malformed-file corpus: truncated or oversized images, PDFs, canvas files and databases produce an error message, never a crash or a hang.

### Compatibility

- [ ] **T-COMPAT-01 (P1)** Commit `tests/compat/0.1.0/` with a `settings.ini`, a theme, a snippet, `hotkeys.ini`, `workspaces.ini` and an index database written by 0.1.0. Every later version must load them, keep unknown keys and write them back unchanged.
- [ ] **T-COMPAT-02 (P1)** Index migration: for every numbered migration, start from the previous schema fixture and assert the migrated index equals one built fresh.
- [ ] **T-COMPAT-03 (P2)** Downgrade: add a made-up newer key and section to each file type and assert a save keeps them.
- [ ] **T-COMPAT-04 (P2)** JSON Canvas: every example in the JSON Canvas spec round-trips, and unknown fields are kept.
- [ ] **T-COMPAT-05 (P2)** Base files: unknown keys and key order survive a view change.

### Text, buffer and input

- [ ] **T-TXT-01 (P1)** Undo tree property test: random edits, undos, redos and branches against a simple reference model, with a fixed seed and many operations.
- [ ] **T-TXT-02 (P1)** Journal replay: any random edit sequence serialized to the journal and replayed gives the same text.
- [ ] **T-TXT-03 (P2)** Unicode: grapheme, word and line breaking and bidi against Unicode's published conformance files (confirm the license first and record it).
- [ ] **T-TXT-04 (P2)** Cursor movement over combining marks, emoji sequences, CJK and mixed-direction text.
- [ ] **T-TXT-05 (P2)** Multiple cursors: every edit and every undo applies to all cursors and merges cursors that touch.
- [ ] **T-TXT-06 (P3)** IME composition event sequences (start, update, commit, cancel) for Japanese, Chinese and Korean, replayed through the UI driver.
- [ ] **T-TXT-07 (P3)** Clipboard: plain text, rich text and files, with the clipboard mocked.
- [ ] **T-TXT-08 (P2)** Very large files: a 50 MB note opens, scrolls and saves without freezing the UI.
- [ ] **T-TXT-09 (P2)** Invalid UTF-8, NUL bytes and mixed line endings are refused or preserved as specified.

### Markdown, links and properties

- [ ] **T-TOK-01 (P1)** Tokenizer coverage invariant: the token ranges cover the whole source with no gaps or overlaps, for every fixture and every fuzz input.
- [ ] **T-TOK-02 (P1)** Incremental tokenizing gives the same tokens as a full re-tokenize after random edits.
- [ ] **T-TOK-03 (P2)** One fixture per Markdown element and per Obsidian-style extension (callouts and their aliases, highlight, comments, block ids, footnotes, inline footnotes, math, tags, wikilink forms, task states), each with a golden for source, live preview and reading mode. Write your own cases: do not vendor the CommonMark spec examples without confirming their license.
- [ ] **T-TOK-04 (P2)** Tag rules: allowed and forbidden characters, numbers-only tags, nested tags, tags inside code and links.
- [ ] **T-LNK-01 (P1)** Link resolution table: every link form (`[[a]]`, alias, heading, nested heading, block, same-note `[[#h]]`, Markdown link with `%20` and `<>`, relative, absolute, non-Markdown files) against a fixture vault with duplicate names in different folders and case or NFC/NFD differences.
- [ ] **T-LNK-02 (P1)** Rename matrix: every link form crossed with rename, move and folder rename, asserting the exact resulting text.
- [ ] **T-LNK-03 (P2)** Unlinked mentions: found by title and alias, not inside existing links or code.
- [ ] **T-PROP-01 (P2)** Property types and values (text, list, number, checkbox, date, date and time, tags, links in quotes), invalid values shown as such and left as written.
- [ ] **T-PROP-02 (P3)** Vault-wide rename and change-type of a property touches only the lines it must.

### Index and search

- [ ] **T-IDX-01 (P1)** Rebuild equals fresh: delete the index, rebuild, compare every table to the original.
- [ ] **T-IDX-02 (P1)** Incremental update: add, edit, rename and delete files on disk while running; the index matches a fresh build.
- [ ] **T-IDX-03 (P2)** Trigram index size on the performance vault stays within the budget (4 times the note text) and the ratio is printed.
- [ ] **T-SRCH-01 (P1)** Operator table: each operator (`file:`, `path:`, `content:`, `match-case:`, `ignore-case:`, `tag:`, `line:`, `block:`, `section:`, `task:`, `task-todo:`, `task-done:`, `[property:value]`), plus `OR`, `-`, parentheses, quotes and regex, with expected result lists.
- [ ] **T-SRCH-02 (P2)** Partial-word, CJK and accent-insensitive matching.
- [ ] **T-SRCH-03 (P2)** Quick-switcher ranking: fuzzy order, alias matches, recently opened first.

### Bases and canvas

- [ ] **T-BASE-01 (P1)** One test per documented function and operator, using the examples in the help pages; separate tests for type coercion, null handling and date arithmetic.
- [ ] **T-BASE-02 (P2)** Formulas referencing other formulas, cycles reported as errors, errors shown in the cell and not crashing the view.
- [ ] **T-BASE-03 (P2)** Filters, groups, sorts and summaries on the performance vault stay within a time budget.
- [ ] **T-CNV-01 (P2)** Canvas editing: add, move, resize, connect, label, color and group, saved and reloaded to the same JSON.

### Graph

- [ ] **T-GRPH-01 (P2)** Layout is deterministic for a given seed, and positions stop changing (converge) within a set number of steps.
- [ ] **T-GRPH-02 (P2)** Filters, orphans, unresolved links, attachments and color groups change the data as specified.
- [ ] **T-GRPH-03 (P2)** Frame time stays within budget and the UI answers input within 50 ms while the layout runs.

### Files, watching and saving

- [ ] **T-FS-01 (P1)** Trash on each OS moves the file to the system trash, `.trash` and permanent modes behave as specified.
- [ ] **T-FS-02 (P2)** Awkward names: Windows reserved names, long paths, trailing dots and spaces, case-only renames on case-insensitive disks, NFC against NFD names, emoji, names containing `# ^ [ ] |`.
- [ ] **T-FS-03 (P2)** Symlinks, junctions and loops.
- [ ] **T-WCH-01 (P2)** External edits, creates, deletes and renames are seen; Exhaust ignores its own writes; a burst of changes is coalesced.
- [ ] **T-WCH-02 (P2)** Polling fallback finds an external edit when the watcher refuses more watches (fake backend).
- [ ] **T-SAVE-01 (P2)** Conflict banner: a note changed on disk while the editor has unsaved changes keeps both versions and offers the diff.
- [ ] **T-SES-01 (P2)** Session restore: tabs, splits, pop-out windows, pinned and stacked tabs, cursor and scroll positions come back after a kill.
- [ ] **T-SET-01 (P1)** Every key in `docs/formats.md` has a default, round-trips through `settings.ini`, and is read by exactly one settings page.
- [ ] **T-SET-02 (P2)** Hotkeys: conflicts are reported, non-US layouts map correctly, every default shortcut in `formats.md` runs its command.

### Appearance and accessibility

- [ ] **T-THM-01 (P1)** Every built-in theme defines every token, and every foreground and background pairing meets the contrast ratio in `formats.md` (4.5:1 for text).
- [ ] **T-THM-02 (P2)** A theme with a missing token falls back to its base; unknown keys are kept; live reload applies within 1 second.
- [ ] **T-A11Y-01 (P1)** Accessibility-tree golden for every screen: every widget has a role and a name, the focus order matches the visual order.
- [ ] **T-A11Y-02 (P1)** Keyboard-only walkthrough of every screen and dialog: nothing is reachable only by mouse, nothing traps focus, Escape closes dialogs.
- [ ] **T-A11Y-03 (P2)** Text size from 50% to 300% and interface zoom: no text is clipped or overlaps in the layout dump.
- [ ] **T-A11Y-04 (P2)** High-contrast themes: all interactive elements have a visible focus ring in the draw list.
- [ ] **T-A11Y-05 (P3)** Right-to-left layout of the whole interface.

### Media, export, import and the rest

- [ ] **T-MEDIA-01 (P2)** Reference audio files decode to known checksums and seek to the right sample; a corrupt file reports an error.
- [ ] **T-MEDIA-02 (P2)** lib-Peep builds and passes its decode tests on x86-64 Linux, Windows and macOS, and on ARM64 where CI offers it.
- [ ] **T-PDF-01 (P2)** PDF export: the file parses, has the expected page count for each page size, landscape and margin option, and is always light-styled.
- [ ] **T-EMB-01 (P2)** Every embed form (note, heading, block, list, canvas, image size, PDF page and height) against a golden; recursive embeds stop at a set depth.
- [ ] **T-MATH-01 (P2)** One golden per supported LaTeX feature (fractions, roots, scripts, matrices, big operators, accents, text); unsupported commands show an error, not a crash.
- [ ] **T-MMD-01 (P2)** One golden per Mermaid diagram type, and invalid diagrams show the source with an error.
- [ ] **T-IMP-01 (P2)** One sample export per importer; check names, links, attachments, dates and that re-importing is safe.
- [ ] **T-FMT-01 (P2)** Format converter is idempotent and changes only `alias`, `tag` and `cssclass`.
- [ ] **T-TPL-01 (P2)** Moment-style date tokens table, daily-note names across month and year ends and leap days, unique-note names never colliding.
- [ ] **T-SPELL-01 (P2)** `PFX`, `SFX`, `REP` and `KEY` rules, each with positive and negative cases, and a user dictionary.
- [ ] **T-SLD-01 (P3)** Slide splitting ignores `---` inside code blocks and frontmatter.
- [ ] **T-VIM-01 (P3)** Key-sequence table for the supported Vim commands.

### Performance and memory

- [ ] **T-PERF-01 (P1)** Typing latency in a 1 MB note stays under 16 ms (median) with live preview on.
- [ ] **T-PERF-02 (P1)** On the performance vault: cold index under 10 seconds, search under 100 ms, warm start under 1 second, memory under 200 MB. Record the numbers each run so regressions are visible.
- [ ] **T-MEM-01 (P2)** Open and close every screen 1,000 times under ASan with leak checking; memory returns to baseline.
- [ ] **T-MEM-02 (P3)** Run the unit tests under Valgrind once per release.

### Packaging

- [ ] **T-PKG-01 (P2)** Smoke test of each package (zip, AppImage, dmg): it starts, opens a vault, shows a note and exits with code 0.
- [ ] **T-PKG-02 (P2)** The core install stays within the size budget and contains no network-capable add-ons.

## Manual checklist (not run by CI)

Do these before each release and note the OS and version tested:

- [ ] Screen reader reads the editor, file tree, settings and graph list: NVDA (Windows), VoiceOver (macOS), Orca (Linux).
- [ ] IME typing in the editor and search box: Japanese, Chinese, Korean.
- [ ] High-DPI and mixed-DPI monitors; Wayland and X11.
- [ ] Copy and paste between Exhaust and other apps, including images and rich text.
- [ ] Moving files to the real system trash and restoring them.
- [ ] A vault on a network share, an external drive and a synced folder.
- [ ] Power-cut test: type, pull the power or end the VM, relaunch, check nothing was lost.
- [ ] A long session (several hours) on the performance vault with no growth in memory.
