# Exhaust 0.0.0

A robust and personable notepad that doesn't get in your way. Notes, journals, knowledge bases and project plans, linked together.

Exhaust's goal is feature parity with Obsidian's documented feature set, in a private, native program. This README is the spec. Features marked *(later)* may be stubs in the first demo. Items marked *(optional)* use the network and are off by default. Other features that are off by default, such as Vim mode, are not marked *(optional)*. The technical design is at the end.

## Values:

- **Customizable, but not overwhelmingly**: Exhaust offers settings to change the workflow of the notepad to fit your needs. You can even set the default size of a new exhaust window. Despite this, it is not overloaded with features. We include a robust kit of text editing features, some quality of life things, and allow you to control which features you want and where you want them. As well as what you want everything included to look like.
- **Aesthetic**: The design of Exhaust is meant to be simple and pleasant to the eye. It is inspired by the design of Midori MD notebooks.
- **Simple**: Exhaust provides a simple environment in which to use complex features. And where features present in other apps do not go directly towards text, we will drop those features.
- **Small, but not at the cost of features**: Exhaust is as small as it can be without dropping anything in this README. The program may be as large as it needs to be to fit all of these features, but the core install stays within a fixed size budget (see Technical design); optional libraries ship separately.
- **Private**: What you write is your business. Simple as.
- **Nothing is ever lost**: Exhaust saves continuously. Closing the app, a crash, a kill or a power cut never loses what you typed.

## Rules

- Notes are plain Markdown files in a folder you choose. Exhaust never moves, renames or reorganizes them behind your back.
- Exhaust saves continuously: every edit is journaled within 200 ms and notes are written to disk after a short idle, so closing, a crash, a kill or a power cut never loses what you typed. Typing in a note is the action that lets Exhaust write it. See Saving.
- No network requests, telemetry or accounts unless you turn on an *(optional)* feature.
- **Updates**: there is no auto-updater. An optional manual "check for updates" button *(optional)* asks the network only when you press it.
- Every feature below can be switched off. Built-in features such as Graph, Canvas and Bases are separate toggles in Settings.
- Notes are not encrypted by Exhaust; use full-disk encryption.

## Vaults and files

- **Vaults**: a vault is a folder of Markdown files. A vault button at the bottom of the file tree switches between vaults. Create, open and remember several. Manage them from the vault list: rename, move, remove from the list (never deleting files), create a vault from an existing folder, and transfer settings from one vault to another. Choosing a folder uses the operating system's native folder-picker dialog (SDL3 provides one on Windows, Linux and macOS), and on first launch, when no vault is known, Exhaust shows the vault manager.

*Build status (sub-slice 2e):* `exhaust` with no argument opens the vault used last, or shows the vault manager when none is known; `exhaust --vaults` shows it, and so does the vault button at the bottom of the file tree. Like many note apps, each vault opens in its own window (a new process), so the manager is a small chooser window that closes once a vault is opened. Menu actions: **Rename** changes the name shown in the list (the folder keeps its name, so the vault's journal and session, which are keyed by its path, are never orphaned); **Move** moves the vault's folder into another folder on the same drive, refuses to replace anything, and moves the vault's recovery data with it; **Copy settings to...** adds the settings, hotkeys, themes and snippets of one vault to another without replacing anything the target already has; **Remove from list** touches no file. The synced-vault entry is a disabled stub labelled *(optional, later)*.
- **File explorer**: a tree of folders and notes. Create, rename, move, delete and sort. Folders shown here are the real folders on disk. Sorting and grouping are done inside the app, stored in settings, and never rename, move or reorder anything on disk. Only create, rename, move and delete, which you do yourself, change files. Auto-reveal the open note in the tree, and expand or collapse all folders. Each note's More-options menu offers open in default app, show in file manager, copy path (from the vault, or from the system root) and export to PDF.
- **Open anything**, with exactly these file types: Markdown (`.md`), bases (`.base`), JSON Canvas (`.canvas`), images (`.avif`, `.bmp`, `.gif`, `.jpeg`, `.jpg`, `.png`, `.svg`, `.webp`), audio (`.flac`, `.m4a`, `.mp3`, `.ogg`, `.wav`, `.webm`, `.3gp`), video (`.mkv`, `.mov`, `.mp4`, `.ogv`, `.webm`) and PDF (`.pdf`). Other file types are left alone. Audio, video and PDF need the optional media and PDF libraries; without them Exhaust offers "Open externally". Playback depends on the codecs available. *Build status (sub-slice 6c-i):* a picture file (`.avif`, `.bmp`, `.gif`, `.jpeg`, `.jpg`, `.png`, `.svg`, `.webp`) opens in a tab of its own, read and decoded on the service thread and shown fitted to the pane (wheel zoom about the pointer, drag to pan, double click for the picture's own size, `+` `-` `0` `1` keys, a checkerboard under transparency). JPEG pictures are turned by their EXIF orientation. Image file cards of a canvas show the picture. Not built: animated GIF and WebP (the first frame is shown), AVIF image sequences, overlays and ICC profiles, HDR tone mapping, and pictures in pop-out windows (they say so). Pictures in notes are 6c-v. The details are in `docs/formats.md` (*Pictures (6c-i)*). *Build status (sub-slice 6c-ii):* an audio file opens in a tab with a play and pause button, a position bar, a volume bar and the keys Space, Left, Right, Up, Down and Home. WAV (PCM of 8 to 32 bits and float, A-law, mu-law, IMA and Microsoft ADPCM) and FLAC are decoded by lib-Peep, MP3 by dr_mp3 and Ogg Vorbis by stb_vorbis, all of the file in memory on the service thread; output is SDL3's, and the audio callback takes no lock, allocates nothing and reads no file. `.m4a`, `.webm` and `.3gp` need the media add-on (6c-iii) and offer *Open externally*. Not built: a play list or queue, the playback of audio embedded in a note (6c-v), keeping the volume between runs, and Intel Macs (lib-Peep's x86-64 code is ELF-only). The details are in `docs/formats.md` (*Audio (6c-ii)*). *Build status (sub-slice 6c-iii):* a video file (`.mkv`, `.mov`, `.mp4`, `.ogv`, `.webm`) and the audio files the built-in decoders do not take (`.m4a`, `.webm`, `.3gp`) open in a media tab played by **libmpv, loaded at run time** (never linked; from the add-on folder `addons` next to the program, or the system's): the picture is drawn by libmpv's software renderer on the player's own thread at the size of the pane, and the tab has the same button, position bar, volume bar and keys as the audio tab. Without libmpv the tab says the media add-on is missing and offers *Open externally*. libmpv is given only the file's path (scripts, the user's mpv configuration, youtube-dl and network playlists are off). Not built: subtitles and audio-track choice, full screen, a picture in a pop-out window. The details are in `docs/formats.md` (*libmpv (6c-iii)*). *Build status (sub-slice 6c-iv):* a PDF opens in a tab as a column of pages drawn by **PDFium, loaded at run time** (never linked; the add-on folder `addons`, or the system's): its own thread renders the pages near the window and reads text, links and search results, so the interface never calls it. The tab has *Contents* (the outline), *Fit width*, *Fit page*, zoom, search (type in the box; match case, highlight all, next and previous), text selection with Ctrl+C, a click on a link inside the document, and Ctrl+Shift+C to copy a link to the selection, `[[file.pdf#page=3&selection=120,148]]` (the page, then the first character and the one after the last). **Privacy:** no form-fill environment is started (no script or form action can run), PDFium is given the file from memory, and a link to a web address is only reported: the program asks before it opens it in the system browser. Without PDFium the tab says so and offers *Open externally*. Not built yet: opening a `[[file.pdf#page=...]]` link from a note (the viewer can go to a page and a selection; the link router is 6c-v), embeds in notes (6c-v), selection across pages, rotated pages' text boxes. Details in `docs/formats.md` (*PDF (6c-iv)*).
- **Excluded files**: patterns that hide files from search, links and the graph.
- **Link-safe renames**: renaming or moving a note updates every link to it. It asks first by default; you can make it automatic or off. It covers wikilinks, embeds, Markdown links (URL-encoded and relative), links inside properties, `#heading` and `#^block` references, `.canvas` files, `.base` files and bookmarks.
- **Note names**: a name cannot contain `# ^ [ ] |` or `:`, a `%%` pair, or a Windows reserved name (such as `CON` or `NUL`). Links match names without regard to case and after Unicode (NFC) normalization.
- **Saving**: Exhaust saves continuously.
  - Every edit is written to an append-only recovery journal within 200 ms.
  - The note file itself is written after a short idle (1 second by default) and at the latest every 5 seconds of continuous typing. A note is also saved when focus leaves it, when you switch tabs and when the window closes.
  - The same applies to canvases, bases, bookmarks and every other file you edit in Exhaust.
  - Writes are atomic: Exhaust writes a temporary file next to the note, flushes it to disk, then renames it over the note. It never writes a partial note. It preserves the file's symlink, permissions, line endings (CRLF or LF) and byte-order mark. Notes are UTF-8.
  - On a clean close, SIGTERM, SIGHUP, Windows session end and macOS terminate, Exhaust flushes everything before exiting.
  - After a crash, kill or power cut, the next launch replays the journal and restores the text, with a banner saying so. If the note file on disk changed in the meantime, the conflict banner (with a diff) appears and both versions are kept.
  - A new note that has had nothing typed in it is not created on disk.
  - If a write fails (disk full, permission denied, file locked), the text stays in the journal, a persistent error names the file, and Exhaust retries. Unsaved text is never discarded.
  - Nothing in this changes the rule that notes are only written through an action you take: typing in a note is that action.
- **Trash**: deleted notes go to the system trash, to a `.trash` folder in the vault, or are deleted permanently, as you choose, with an optional confirmation.
- **Symbolic links**: followed, with loops detected.
- **Configuration folder**: settings, themes, snippets, hotkeys and workspaces live in a `.exhaust` folder inside the vault, in plain text. The search index and other caches live in the operating system's cache folder, keyed by vault, never inside the vault, so file-sync tools cannot corrupt them. Settings has a *Rebuild vault cache* button. The recovery journal and the session state are your data, not a cache: they live in the operating system's local-data folder, keyed by vault, never in the cache folder (the OS may clear it) and never inside the vault (sync tools would copy them between devices). The exact folders are in [`docs/formats.md`](docs/formats.md#journal-and-session-state).
- **Import**: Markdown and plain text folders, HTML, CSV and Textbundle. Importer templates control how imported notes are named and laid out. Importers for Apple Journal, Apple Notes, Bear, Craft, Evernote, Google Keep, Logseq, OneNote, Notion, Roam, Tomboy/Gnote and Airtable are listed as disabled *(later)* entries. *Build status (sub-slice 6e-v):* the command *Importer: Open format importer* lists the formats and imports a Markdown, plain-text, HTML, Textbundle or CSV source (a folder, or a file for CSV, chosen in the system's dialog) into a folder of the vault on a thread of its own, with a dialog that has *Cancel*. **A note or file already in the vault is never replaced** (a name that is taken gets a number) and the source is never changed. HTML is converted to Markdown, a CSV row becomes a note with properties, a Textbundle's assets are copied and relinked. The *Importer* settings page has the destination folder, the name pattern, *keep the source's folders* and the importer template. The other applications' importers are in the list, muted, as *(later)*. See `docs/formats.md` (*Import*).
- **Backups**: because everything is plain files, any backup tool works.

## Writing

- **Markdown**: headings, bold, italic, strikethrough, highlight, lists, task lists, quotes, code blocks, tables, horizontal rules, footnotes, comments, math, and Mermaid diagrams (flowchart, sequence, class, state, ER, pie and gantt).
- **Callouts**: typed, titled and foldable (`+` or `-`) blocks, nestable. The types, each with its own color and icon, are `note`, `abstract` (aliases `summary`, `tldr`), `info`, `todo`, `tip` (`hint`, `important`), `success` (`check`, `done`), `question` (`help`, `faq`), `warning` (`caution`, `attention`), `failure` (`fail`, `missing`), `danger` (`error`), `bug`, `example` and `quote` (`cite`). The type is not case-sensitive and unknown types show as `note`. Custom callouts, with your own color and icon, are made with style snippets.
- **Live preview**: formatting shows as you type, with the syntax revealed under the cursor.

*Build status (sub-slice 3b):* source mode and live preview work in the note editor (the `Md` ribbon button and the *Toggle Live Preview/Source mode* command switch a tab). Headings are scaled inside the normal row height (up to 1.3 times; rows do not yet change height), lines wrap at the width of the editor (since 4d), and math, embeds, images, tables and HTML are shown as source until their renderers (6c, 6d) exist. Reading mode and folding came with 3c.
*Build status (settings pass after 8c):* ten settings that used to do nothing are now read. **Typing helpers** (`smart_lists`, `auto_pair_brackets`, `auto_pair_markdown`; `docs/formats.md`, *Typing helpers*): Enter in a list or quote continues it (numbers count up, tasks start unchecked) and an empty item ends it; `(`, `[`, `{` and `"` write their pair, a closing character types over the one that is there, Backspace between a pair removes both, and with text selected the mark wraps it (`*`, `_`, `~`, `=`, `$`, backtick; the backtick also pairs on its own). `[[` gives `[[]]` with the link list open. They are off in plain fields, code, math and front matter (Markdown marks), with several cursors, and for pasted text. **Display**: *Readable line length* centers the text of the editor in a column of 720 px (the reading view always did), *Line numbers*, *Indent guides* and *Strict line breaks* (reading mode, slides, export) work. **Paste HTML as Markdown** converts a copied web page when you paste. **New note location** is used by the command *Create new note*. The settings the program still does not act on (the fonts, the language, the window frame and native menus, translucency, spelling languages, right-to-left text, focusing new tabs, link format, wikilinks on or off, deleting attachments, the name of the settings folder, hardware acceleration and the slow-start notice) show a disabled *Not in this version* button instead of a control that does nothing (ISSUES 47). Four of them (hardware acceleration, Ctrl+wheel font size, focus new tabs, wikilinks) had a default of on; as stubs they read as off until they are built.
- **Source mode and reading mode**: switch per note.
- **Folding** of headings and lists.

*Build status (sub-slice 3c):* reading mode (`Ctrl+E`, or *Default view for new tabs* in the editor settings) shows a note as formatted pages with the callout, list, task, table, code, math, footnote and tag styling; images and embeds are placeholders until 6d and math is shown as its source until 6c (no math renderer yet), links open from the page (web links in the system's browser, note links when the name matches). Folding works for headings and list items in source mode and live preview: click the triangle in the left margin, or use the *Fold*, *Unfold*, *Fold more*, *Fold less* and *Toggle fold on the current line* commands; folds are not saved with the session yet.
- **Find and replace** inside a note, with regular expressions.

*Build status (sub-slice 3d):* `Ctrl+F` opens a find bar over the note, `Ctrl+H` adds the replace row: a find field, switches for case, whole words and regular expressions (PCRE2; replacements take `$1`, `${1}`, `\n` and `\t`), previous and next (Enter and Shift+Enter), a count, every match highlighted, *Replace* and *Replace all* (one undo step). Find works in the editor, not yet in reading mode.
- **Multiple cursors** and **rectangular selection**: `Alt+click` adds a cursor, `Ctrl+Alt+Up` and `Ctrl+Alt+Down` add one above or below, and dragging with `Alt+Shift` held selects a column of text.
- **Editing shortcuts**: the default shortcuts for copying, deleting, moving the cursor and selecting text, for Windows and Linux and for macOS, are listed in [`docs/formats.md`](docs/formats.md#default-editing-shortcuts). Smart list continuation and indent follow the Editor settings. Shortcuts work on non-US keyboard layouts.
- **Spell check** (Exhaust's own checker, English (US) dictionary included, more added as word lists) and a **word count** in the status bar.

*Build status (sub-slice 3e):* unknown words get a wavy line (not in code, math, links' addresses, tags or front matter, and not the word you are typing); the commands *Spelling: Replace with the next suggestion* and *Spelling: Add word to dictionary* work on the word at the cursor (there is no context menu yet to pick from; added words go to `.exhaust/dictionaries/custom.txt` in the vault); *Toggle spellcheck* flips the setting. The status line shows the word count of the note, or of the selection. Only English (US) is available in 0.1.
- **Export to PDF**: from the command palette or a note's More-options menu. Options: page size (A3, A4, A5, Legal, Letter or Tabloid), landscape, margin (Default, Minimal or None), downscale percent, and include the file name as the title. Exports are always light-styled. *Build status (sub-slice 6e-iv):* *Export to PDF...* (the command palette, the explorer menu of a note, the pane menu) asks for the file in the system's save dialog (and again before it replaces a file), then lays the note out and writes the PDF on a thread of its own, with a dialog that has *Cancel* and the page and percent in the status bar; the options are the *Export to PDF* page of the settings. The file is always light-styled, its text is real text (selectable and searchable: the fonts are embedded as subsets with a text map), and it holds the headings, lists, tasks, callouts, code, tables, footnotes, links to web addresses, pictures, equations and Mermaid diagrams (as vector shapes) of the note; audio, video, PDF and canvas embeds become cards with the file's name. Not built: characters the built-in fonts lack (CJK, emoji, Arabic, Hebrew) print as `?`, no outline, internal links or page numbers. See `docs/formats.md` (*Export to PDF*) and `docs/ISSUES.md` 72 and 73.
- **Embedded content**: notes, headings, blocks, lists, canvases, images, audio, video and PDFs, with `![[file]]` and Markdown syntax. Images take a size: `![[img.png|640x480]]` or `![[img.png|100]]`. PDFs take a page and height: `![[f.pdf#page=3&height=400]]`. External image URLs need the network, so they are *(optional)* and off by default, showing a placeholder instead. Web links open in the system browser; Exhaust has no embedded browser. *Build status (sub-slice 6c-v):* in reading mode a line that is only `![[Note]]`, `![[Note#Heading]]` or `![[Note#^block]]` shows that text in place as a quotation headed by the note's name (a note that embeds itself is shown once; its own embeds stay as written); a paragraph that is only `![[photo.png|640x480]]` or `![[photo.png|100]]` (or a Markdown image of a vault file) is drawn as the picture at that size; `![[song.flac]]`, `![[clip.mp4]]`, `![[f.pdf#page=3&height=400]]` and `![[board.canvas]]` are cards with the file's name: a click plays an audio file with the one player (and pauses it) and opens the others in a tab (a PDF at its page); `[[f.pdf#page=3&selection=120,148]]` opens the PDF at that text; an external image address shows a placeholder and nothing is fetched (the optional setting is not built). Not built: a video or a PDF page drawn inside the note (the card opens it), audio and video controls inside the note beyond play and pause, embeds in the editor's live preview. See `docs/formats.md` (*Embeds (6c-v)*). *Build status (sub-slice 6d-i):* in reading mode `$$ ... $$` blocks are drawn as equations, centered, and `$...$` inside a line of text; fractions, roots, scripts, sums, integrals and limits, stretching delimiters, matrices and cases, accents, alphabets (`\\mathbb`, `\\mathcal`, ...) and about 130 symbols are laid out with TeX's rules and the numbers of STIX Two Math's `MATH` table (built in; `docs/formats.md`, *Math*); a formula that cannot be parsed stays as its source in the error color. Not built: math in the editor's live preview and source mode (they show the source), equation numbers, `\\substack`, `\\color`, `\\xrightarrow`, over- and underbraces, `align`, `\\newcommand`. *Build status (sub-slice 6d-ii):* in reading mode a code block whose language is `mermaid` is drawn as a flowchart (`flowchart` and `graph`, all directions, 12 node shapes, link styles with labels and heads, chains, `&`, nested subgraphs) or a sequence diagram (participants, actors, the eight arrow forms, activations, notes, `loop`, `alt`, `opt`, `par`, `critical`, `break`, `rect`, `autonumber`) with Exhaust's own layout and the theme's colors; one that cannot be parsed stays as its source with the reason under it. Not built: colors and styles written in a diagram (`classDef`, `style`, `linkStyle`), curved links, diagrams in the editor's live preview. See `docs/formats.md` (*Mermaid*). *Build status (sub-slice 6d-iii):* class diagrams (members, annotations, generics, the relation types with cardinalities and labels), state diagrams (descriptions, start and end points, composite states, choice, fork and join, notes), entity-relationship diagrams (attributes with keys, the cardinality marks, identifying and non-identifying lines), pie charts (percentages, legend, `showData`, `title`) and gantt charts (sections, dates, durations, `after` and `until`, milestones, `done` `active` `crit`, `axisFormat`) are drawn the same way. Not built: the styles written in a diagram, the date formats of gantt charts other than `YYYY-MM-DD`, skipping weekends, a `today` line, diagrams in the editor's live preview. *Build status (sub-slice 6e-i):* Daily notes (open today's, the next and the previous; made from the template when missing, in the configured folder, never replacing a note) and Templates (insert a template from the template folder with its properties merged into the note's, insert the current date and time) work as described in `docs/formats.md` (*Templates and daily notes*); the date format may hold folders (`YYYY/MM/YYYY-MM-DD`). Not built: the calendar view of daily notes (the README lists it as optional in the sidebar), `{{date}}` offsets such as `+1d`, templates in the slash menu's own picker. *Build status (sub-slice 6e-ii):* Unique notes (a note named by the prefix format, never colliding: `-2`, `-3`; a link to a new one inserted at the cursor) and the Note composer (extract the selection or a heading's section into a new note, leaving a link, an embed or nothing; merge the open note into another, merging their properties, pointing every link at the other note and deleting the merged one) work as described in `docs/formats.md` (*Unique notes and the note composer*). Not built: choosing the note to merge into from a list (its name is typed), links to a `^block` that moved with an extracted section. *Build status (sub-slice 6e-iii):* Slides (off by default; *Slides: Start presentation*) shows the open note as slides in a tab of its own, split at the lines of three or more hyphens that follow a blank line (not in the properties, code, math or comments), with larger text and Right/Left, Space, Home, End and Escape. Not built: a full-screen window, speaker notes, transitions, vertical slides.
- **HTML** in notes: a safe subset of tags, drawn by Exhaust itself.
- **Slash commands**: type `/` at the start of a line or after a space for a menu of the editor commands, narrowed as you type (fuzzy matching, Up and Down, Enter or Tab to run it, Escape or a space to close it). The feature is off until *Slash commands* is turned on in Core plugins. Editor commands whose features are not built yet are listed disabled. The text formatting commands that work now: bold, italic, strikethrough, highlight, code, inline math, comment, headings (set, remove, cycle), bullet and numbered lists, quote, checkbox status, indent and unindent list items, move line up and down, delete paragraph, horizontal rule, code block, callout, math block, table, footnote, links, embeds, tags, clear formatting and adding cursors.
- **Audio recorder**: record straight into a note *(later)*. *Build status (sub-slice 6e-v):* a disabled switch in *Core plugins* (under *Not in this version*); nothing records.
- **Vim mode** *(later)*: not in 0.1.0; the switch in Editor settings is shown disabled and labelled (`vim_mode` is a stub key: it cannot be turned on).

## Links

- **Wikilinks**: `[[Note]]`, `[[Note|alias]]`, `[[Note#Heading]]`, `[[Note#^block]]`, plus ordinary Markdown links. Suggestions appear as you type.
- **Backlinks**: a panel of notes that point at the open note, including unlinked mentions. Backlinks can also be shown at the bottom of the document.
- **Outgoing links**: a panel of everything the open note points at.
- **Aliases**: alternate names for a note that links can use.
- **Page preview**: hover a link to see the note.
- **Tags**: `#tag` and `#nested/tags`, a tag pane, and search by tag.
*Build status (sub-slices 4a-i to 4a-iv):* the index (`include/exhaust_index.h`, `src/index/`) is a SQLite database in the OS cache folder with trigram full-text search, lines, sections, blocks, tasks, names, links, tags and properties, filled by an indexer thread (`ex_indexer_start`) from the notes and rebuilt on demand; its tables are listed in [`docs/formats.md`](docs/formats.md#index). Links resolve by name, path or alias after NFC and case folding (`include/exhaust_links.h`): outgoing links, backlinks, unlinked mentions (found through the trigram index, so only the notes that can hold the name are read) and page previews are functions of the index. Properties are read with libyaml and edited as text (`include/exhaust_props.h`); renaming or moving notes rewrites every link to them (`include/exhaust_rename.h`). These are shown by the panels and dialogs of sub-slice 4c (below).
- **Properties**: typed metadata at the top of a note (text, lists, numbers, checkboxes, date, date and time, links) kept as plain YAML. The default properties are `tags`, `aliases` and `cssclasses`; `cssclasses` adds style classes to the note. A properties pane shows every property in the vault, and you can rename a property or change its type across the whole vault as an action you choose.

## PDF viewer

PDFs open in a tab and embed in notes (needs the optional PDF library).

- **Navigation**: a table of contents, fit width, fit height, and zoom.
- **Search**: find in the PDF, with match case and highlight all.
- **Copy text** from the page.
- **Links to a selection**: `[[file.pdf#page=1&selection=...]]` opens the PDF at that selected text.
- **Annotations** are not supported (see Non-goals).
- **Private**: the viewer makes no network requests and runs no scripts from a file; a link to a web address asks before it opens in the system browser.

## Graph

- **Graph view**: notes are circles, links are lines, busier notes are bigger. Hover to highlight neighbours, click to open, right-click for actions, scroll to zoom, drag to pan, arrow keys and `+`/`-` too.
- **Graph display**: arrows, a text fade threshold, node size and link thickness.
- **Local graph** for the open note, with adjustable depth.

*Build status (sub-slice 5a):* the **Graph view** button in the ribbon (or `Ctrl+G`) opens the graph of the whole vault in a tab: a circle for every note, bigger for a note with more links, a faint circle for a name that is linked and does not exist yet (clicking it creates the note), a line for every link, and the open note in the accent color. The layout (the Barnes-Hut approximation of forces, as in d3-force) runs on its own thread and the picture settles in a second or two; it follows the layout until you drag to pan or use the wheel to zoom about the pointer. Hover a node to highlight it, its neighbours and their lines and to fade the rest (with Ctrl held, a page preview of the note); click it to open the note; right-click it for the menu a note has in the explorer. Labels appear when zoomed in, the busiest first. With the keyboard: arrow keys pan, `+` and `-` zoom, `0` fits the graph, Page Up and Page Down step through the nodes, Enter opens the selected one. Pan and zoom are not saved; the local graph, animation and the list for the keyboard (5c) are not built yet.

## Organizing and structure

- **Canvas**: an infinite board for notes, images, web links, text cards and groups, joined by labeled arrows. Saved as `.canvas` in the open JSON Canvas format. *Build status (sub-slice 6a):* a `.canvas` file opens as a board (the ribbon's Canvas button and *Canvas: Create new canvas* make one). Text cards, file cards (the start of the note, read on the service thread), link cards, groups and edges with labels, colors and arrow ends are drawn; only what is in view is laid out and text appears only above the zoom set in the Canvas settings. Pan, zoom, select, move (a group takes its cards), resize, snap to the grid and to other cards, draw an edge from the dots beside a card, edit a card's text in place, copy and paste between canvases, color, delete, and undo and redo; every change is one edit of the file's document, so it goes through the recovery journal and the autosave. Keys the file has that Exhaust does not know, and their order, are kept, and a canvas in the layout of the JSON Canvas samples is written back byte for byte. A file that is not valid JSON is shown as a message and never written. Renaming or moving a file rewrites the cards that point at it. The details are in `docs/formats.md` (*Canvas (6a)*). Not built yet: image cards draw the file name until the image viewer of 6c, card text is shown as plain Markdown source (headings only) until 6c-v, *Export as image* is unbound, and a file card's heading or block (`subpath`) is shown but not followed when the card is opened.
- **Bases**: database-style views of your notes and their properties, with filters, sorting, grouping, summaries (built-in and custom), formulas and functions (72: the 68 of the Bases help and four list statistics, see `docs/formats.md`). Expressions use the `note.`, `file.` and `formula.` namespaces and the `this` object. A view can have a limit, copy to the clipboard and export CSV. Layouts and their settings: table (row height), list (markers and separators), cards (card size and image property), kanban (columns) and map. Saved as `.base` files, or embedded in a note as a code block. `.base` files belong to Exhaust, so it may rewrite them (keeping any keys it doesn't know); notes are never reformatted. The map layout needs map tiles from the network, so it is *(optional)* and off by default, with a tile address you set; without it, it plots coordinates on a plain grid. *Build status (sub-slices 6b-ii and 6b-iii):* a `.base` file opens in a tab as a table, list, cards, kanban or map (the view menu adds, renames and deletes views and switches between them; Results copies the view as a Markdown table, exports CSV or sets a limit; Settings has the row height, list markers and separator, card size and image property, and kanban column width; Edit source shows the YAML). Opening a base never writes it; a change from a menu is one edit of the file, so it goes through the journal and the autosave and Undo gives back the same text. A base block or an embed of a `.base` file in a note is shown in reading mode as its results. Comments in a `.base` file are not kept when Exhaust rewrites it; keys it does not know are. The map plots a plain grid (tiles and the tile address setting are not built, ISSUES 59). Not built yet: Sort, Group, Filter and Properties menus (edit them in the source), a search box, drag to reorder, editing cells. The details are in `docs/formats.md` (*Bases files and views*).
- **Daily notes**: a note per day from a template, with an optional calendar. Date formats use Moment-style tokens, such as `YYYY-MM-DD`.
- **Templates**: insert a template with date, time and title variables, using Moment-style date tokens (`{{date:YYYY-MM-DD}}`). The template's properties are merged into the note's own.
- **Unique note creator**: timestamp-named notes for Zettelkasten work.
- **Note composer**: merge two notes, or split a selection into a new note, with links updated. An optional template file sets the text of the extracted note.
- **Slides**: present any note, with `---` between slides.
- **Format converter**: migrates old frontmatter across the whole vault (`alias` to `aliases`, `tag` to `tags`, `cssclass` to `cssclasses`). It runs only when you ask, after a warning to back up your notes first. *Build status (sub-slice 6e-iv):* the command *Format converter: Frontmatter migration* asks first (and says to back up the vault), then renames only those three keys in every note that has them, leaving a note that already has the new key alone (`docs/formats.md`, *Format converter*).

### Themes

Themes can be changed at any time, in Settings, without restarting. The theme and snippet file formats and every token name are in [`docs/formats.md`](docs/formats.md).

- **Switching**: choose Light, Dark or Follow system. A theme can also be set for each vault.
- **Built in**: Exhaust Dark, which uses the colors of the reference screenshots (navy background, lilac text, purple accent), Exhaust Light, and a high contrast version of each. The exact color values are in the Palette table in [`docs/formats.md`](docs/formats.md#palette); Light and the high contrast themes are derived from it, since no screenshot shows them.
- **Your own**: a theme is a plain text file in the `.exhaust/themes` folder of a vault, or in Exhaust's own settings folder to use it in every vault. It names colors, fonts, sizes, spacing, corner shapes and icons for each part of the interface: the editor, file tree, tabs, sidebars, graph, canvas, callouts and code blocks.
- **Settings editor**: every theme value can also be changed from Settings with live preview and a color picker, so no file editing is needed. Changes you make are saved to a copy of the theme, never to a built-in one.
- **Style snippets**: small extra files in Exhaust's own style format that tweak any part of the interface without replacing the theme. They can be switched on and off one by one.
- **Live reload**: save a theme or snippet file in any text editor and Exhaust updates at once.
- **Contrast check**: Exhaust warns when a color pairing is hard to read.
- **Sharing**: copy a theme file to share it. Nothing is downloaded for you unless you turn on the *(optional)* community directory.
- **Keeping settings**: unknown theme keys are kept and written back unchanged, so themes from newer versions survive a downgrade.

## Extending

- **Plugins**: an open API for new commands, panes, views and file types, written in Lua. Plugins are off until you allow them and declare what they can touch. The manifest format, the Lua API and the permission names are in [`docs/formats.md`](docs/formats.md). A community directory *(optional, later)* needs the network. *Build status (sub-slice 8b):* Lua 5.4.7 runs sandboxed (no `io`, `os`, `package`, `debug` or `load`; a time limit of one second for the loading and for each callback and 32 MB of memory for each plugin; a plugin over a limit is stopped), all plugins on one thread of their own, so a slow or stuck plugin never makes the window wait. A plugin is a folder in `.exhaust/plugins` with a `manifest.ini`; nothing runs until *Allow plugins* is on (*Settings, Plugins*, off by default) and you have turned that plugin on after reading the permissions it asks for (approvals are kept in `.exhaust/plugins.ini` and are asked again when a plugin's permissions or version change). The API of version 1 can add commands (in the palette and the slash menu) and panes (a tab with read-only Markdown), read and write files of the vault, read and replace the text of the open note, show a notice, keep a few settings of its own and react to the events `vault-open`, `file-open`, `file-save`, `file-rename` and `editor-change`. No plugin can use the network: `network` can be approved, and the call fails with *network use is off*. Not built: plugin views and file types, a way to install a plugin from inside Exhaust, `vault.rename` that updates links (ISSUES 77), plugin commands with shortcuts, panes that refresh by themselves, plugin settings pages.
- **Web clipper** *(later)*: a small extension for your own browser that saves pages into the vault. Exhaust itself has no browser. *Build status (8c):* a stub: `extras/clipper/` holds a README that says so, and *Settings, Plugins* has a disabled *Web clipper* row.

## Sync, sharing and publishing *(optional, later)*

- **Sync**: encrypted end-to-end, per-vault, selective by folder, file type and setting. Version history per note, and a log of what synced.
- **Shared vaults**: invite collaborators with owner and editor roles.
- **Publish**: turn chosen notes into a website with themes, custom domains, permalinks, passwords and SEO controls.
- Because plain files are the format, **any** file-sync tool can already sync a vault. These features are a convenience, not a requirement.
- *Build status (8c):* all three are stubs: the *Sync* page of the settings lists Sync, Shared vaults and Publish as disabled, labelled rows, the Core plugins switches of Sync and Publish are disabled, and the vault manager's *Open synced vault* is a labelled stub. The *community directory* of plugins and themes *(optional, later)* is a disabled row on the Plugins and Appearance pages. None of them makes a network request (the test `stubs_disabled` checks the sources for any call that opens a connection).

## Technical design

Exhaust is written in C (C11). There is no web browser or web view anywhere in it. Other languages are used only where they make a feature far easier or reach parity: assembly only in the vendored lib-Peep, Lua for plugins, Rust for the screen reader bridge, up to 150 lines of Objective-C for the macOS platform layer, and JavaScript only for the web clipper extension that runs in the user's own browser, never inside Exhaust. All dependencies must be compatible with the Unlicense; prefer public domain or permissive libraries, and never add GPL or AGPL code. Each dependency and its license is recorded in the table below; confirm the license when the dependency is added. Dependencies are vendored in `third_party/` (source and headers). The large optional libraries (PDFium and libmpv) are not committed: only their headers are, and Exhaust loads them at run time (`dlopen` or `LoadLibrary`). They ship as a separate optional add-on package built from pinned, checksummed upstream releases. Without them, Exhaust offers "Open externally" for PDFs and media it cannot play itself.

### Threads

- **UI thread**: input and drawing only. It never blocks on disk, the index or layout for more than 16 ms.
- **Worker threads**: save and journal I/O, the file watcher, the indexer and graph layout.
- **Messages**: workers talk to the UI thread through a message queue. The UI reads snapshots and never takes a lock that a worker holds.
- **SQLite**: write-ahead logging (WAL) mode, with one writer connection (the indexer) and one reader connection for each thread that needs one.

### Registries

Two registries exist from sub-slice 2d, and every feature uses them from the start, so the settings and hotkey screens only add interface later:

- **Command registry**: each command has an id, a name, a default key and an enabled predicate.
- **Feature-toggle registry**: each built-in feature registers its on/off switch and options.

### Size, safety and quality gates

- **Size budget**: the core install (without the optional PDF and media add-on) is at most 25 MB, checked in CI.
- **Size, measured after slice 5g (2026-11-15):** a Release install is 9,556 KB (about 9.3 MB, 16 MB under the budget): the program 9,448 KB, the rest (licences, fonts, other data) about 108 KB. **Size, measured after 6e-v and after 8c (2026-11-23):** 14,700 KB, then 15,020 KB (about 14.7 MB, 10.5 MB under the budget): the program 14,900 KB, the rest about 120 KB; Lua and the plugin runtime cost about 320 KB. The add-on package is not counted.
- **Sanitizers**: a CI job builds and tests with AddressSanitizer and UndefinedBehaviorSanitizer.
- **Fuzzing**: libFuzzer targets for the Markdown tokenizer, frontmatter, HTML subset, canvas JSON, base expressions and importers.
- **Hardening**: builds use `-fstack-protector-strong` and `-D_FORTIFY_SOURCE=2` where the compiler supports them.

## Non-goals

These Obsidian features are deliberately not part of Exhaust:

- A web viewer and embedded web pages (links open in the system browser).
- Mobile apps.
- Accounts, licenses, payments, credits and the Teams offering.
- A hosted Sync or Publish server. Their settings and interface are stubs; any file-sync tool already syncs a vault.
- Annotating PDFs. Obsidian does not support it either.
- Compatibility with Obsidian's JavaScript plugins. Exhaust has its own Lua plugin API.

## Screenshots

The screenshots in [`screenshots`](screenshots) are the skeleton of how Exhaust should look: Exhaust's layout follows them.

- **Ribbon**: a thin bar of utility buttons down the far left.
- **File tree**: next to it, the vault's files as a tree of folders, with the vault button at the bottom.
- **Tabs**: a row of tabs across the top of the main area.
- **Main area**: panes that can each show a note being edited, the graph view, a canvas or a reference note, side by side.
- **Settings**: a searchable list with Options first, then one entry for each built-in feature that can be switched on or off. The 28 pages in [`screenshots/settings`](screenshots/settings) are the guideline for what every settings page looks like and which options it offers; the Settings section above lists them in my own words.
- **Vault manager**: the list of known vaults with a menu for each, plus buttons to create a vault, open a folder as a vault, and (as a stub) open a synced vault. See `screenshots/vault-manager.png`.
- **Unresolved links**: a link to a note that doesn't exist yet shows dimmed in the text and as a faint node in the graph, joined to the note that links to it. Once the note exists, the link becomes underlined, colored text and the node brightens. See `screenshots/unresolved-link.png` and `screenshots/resolved-link.png`.
- **Hotkeys**: one row per command with its shortcut chip (or "Blank"), a plus button to add a shortcut and a cross to remove one.
- **Wide sidebars** (GitHub issue 2; `screenshots/wide-right-sidebar.webp`, `screenshots/wide-explorer.webp`): a sidebar can be dragged until it fills nearly the whole window, and the main text view in the middle keeps wrapping its text down to one character per line, then collapses to a thin handle that can be dragged to bring it back. In the first screenshot the right sidebar, showing a note, is pulled all the way to the left: it takes almost everything to the right of the explorer, which keeps its width, and only a small handle of the main text view is left between them. In the second the explorer is pulled all the way to the right and the right sidebar is hidden: the explorer takes nearly the whole window and the main text view, showing the note *To Do*, is the narrow column on the right, still readable with its text wrapped to that width. Both sides have a draggable handle. *Build status:* built after sub-slice 4d. The main text view wraps down to one character a row and is hidden below about 20 px, leaving the two divider strips as the handle; dragging either strip brings it back. A sidebar can be dragged over everything except the other sidebar when that one is shown; when it is hidden, the main text view keeps 240 px. The command *Toggle main text view* (no default key) collapses the main text view by widening the right sidebar (the left one when the right is hidden) and restores the old width. A sidebar dragged in until it is under 60 px hides itself (its width is kept), and a thin handle at the window's edge (the right edge for the right sidebar) pulls it back out when dragged. The main text view shrinks with the sidebars all the way down; its text wraps down to one character a row. To confirm by hand against the two screenshots.

Exhaust keeps this arrangement but has its own look: the Midori notebook style, its own icons and wording, and the color palette in [`docs/formats.md`](docs/formats.md#palette) (which follows the screenshots' colors), and light and dark themes. The screenshots are a reference for placement, not artwork to copy; they stay in the repository for now, for development. The UI does not use Obsidian's name or logo.
